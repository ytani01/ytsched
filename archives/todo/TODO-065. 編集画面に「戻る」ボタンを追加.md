## きっかけ

2026-08-26 に、利用者から「編集画面に戻るボタンが欲しい」と挙がった。
編集画面から週表示へ戻る手段が、ブラウザの戻るしか無かった。

## `history.back()` は使えない

`edit.html` には、**同じものが最初からコメントアウトされたまま入っていた**
（`b54376e` の時点で既にあり、2021 年の Perl 版から持ってきたもの）。
`#reply` アイコンを使い、`onmousedown="history.back();"` になっていた。

これはそのまま外して有効にはできない。更新ボタン（`sync`）は
**保存したあと編集画面へリダイレクトして留まる**ので
（`main_handler.py` の `exec_cmd()`、TODO-050）、更新を 2 回押していると
`history.back()` は週表示ではなく**ひとつ前の編集画面**へ戻ってしまう。

`edit.html` には `url_prefix` と `date` が渡っているので、週表示への
GET にした。`doGet()` は `my.js` の既存の関数で、週表示側でも同じ形で
使っている（TODO-050）。

## やったこと

- `src/ytsched/webroot/templates/edit.html`
  - フッター（`id="menu"`）の左端に戻るボタンを足した。
    `onmousedown="doGet('{{ url_prefix }}', {date: '{{ date }}'});"`
  - 戻り先の日付は `orig_date`（行が実際に入っているファイルの日付）では
    なく `date`（表示していた日付）にした。押す前に見ていた週へ戻す
  - 空きの `col-4` を `col-2` に縮めて、桁の合計を 12 に保った。
    並びは 戻る・更新・確定・複製（新規のときは空）・空き・削除
- `src/ytsched/webroot/static/js/my.js`
  - **TODO-068 の分**。`pageshow` の listener を足し、`event.persisted`
    が真のときだけスピナーを消す（下記）

`icons.svg` の 23 個のうち、実際に使われていないのは `#reply` だけだった
（唯一の参照が上のコメントの中）。利用者の希望どおり、未使用のものを使えた。

## 決めたこと

- **未保存の変更があっても確認しない。** 押したらそのまま戻る
- **検索モード中に編集へ入った場合の戻り先は考えない。** 検索語は
  `conf.json` に残るので、週表示へ移っても検索モードのままになりうるが、
  この項目では触らない

## TODO-068（スピナー）を一緒に直したが、確かめられていない

TODO-068「編集画面から週表示に戻ったとき、スピナーが表示されっぱなしに
なる」は、項目に「TODO-065 に入れられるなら TODO-065 で対応」とあったので
ここで直した。

スピナーを消しているのは各ページの `load` ハンドラだけで、**bfcache
（戻る/進むで復元されるキャッシュ）から復元されたときは `load` が起きない**。
`doGet()` が出したスピナーがそのまま残る。`pageshow` で消すようにした。

**この修正が実際に効くかどうかは、確かめられていない。** headless の
chromium では、`--enable-features=BackForwardCache` を付けても bfcache が
働かず（戻ったときに静的ファイルを取り直し、`onloadHdr` が 2 回動いた）、
不具合そのものを再現できなかった。`event.persisted` が偽なら即 return
するので通常の読み込みには影響しないことは、コードを見て確かめてある。
**実機のブラウザでの確認が要る。TODO-068 は開けたままにした。**
→ 2026-08-26 に利用者が実機で確認し、TODO-068 は閉じた
（[TODO-068](TODO-068.%20編集画面から週表示に戻ったとき、スピナーが表示されっぱなしになるのを修正.md)）。
