# TODO-025. 文書の確認を分ける仕組みを決める

見込み: main = Opus 5 / effort high、担当 = main のみ
実施: main = Opus 5 / effort medium、担当 = main のみ

## きっかけ

TODO-021 で、`characterization test` のことを「足場」と呼ぶ造語を作り、
利用者から 2 度指摘された（`~/.claude/CLAUDE.md` の「造語を使わない」
「専門用語は無理に和訳しない」の両方に反していた）。

問題は語彙ではなく、**書いた本人が自分の造語に気づけない**こと。造語は
書いた瞬間も読み返したときも意味が通るので、自己点検では捕まらない。

同じ形の問題を、コードでは既に解いてある。「実装した本人は『動くはず』で
済ませてしまう」ので確認を別の担当に分ける、というのが TODO-017 で決めた
基準。文書には、それが適用されていなかった。

この項目では**仕組みを決めるところまで**をやり、定義ファイルと hook を
実際に作るのは TODO-026 にした。

## やったこと

### 「足場」がどこから入ったかを調べた

`git log -S足場 --all -- 'archives/*'` で見ると、リポジトリに入った
コミットは `95895c1` の 1 つだけで、入っているファイルは
`archives/agents/TODO-021/implementer1-report.md` と
`reviewer-report.md` の 2 つだけだった。

**依頼書には 1 度も書かれていない。** 項目を立てたときは「依頼書に
書かれたあと、担当 5 人の報告へ写されて広がった」と書いたが、記録は
そうなっていない。出どころはファイルに残らない main の指示文（Agent
へ渡す prompt）で、そこから担当 2 人の**報告**へ写っている。

依頼書だけを見る仕組みでは捕まらない、ということがここで分かった。

### 「初出の語を洗う」やり方を実測した

文書が追加されたコミットの 1 つ前を基準にして、その文書に出てくる語を
`git grep -c` にかけ、前例が 0 件の語を数えた。語の抜き出しは、カタカナ
3 文字以上と漢字 2 文字以上を正規表現で拾う雑なやり方（下記）。

| 文書 | 候補 | 前例なし |
| --- | --- | --- |
| TODO-021 `implementer1-report.md`（足場が入った文書） | 89 語 | **15 語** |
| TODO-021 `reviewer-request.md` | 78 語 | 3 語 |
| TODO-022 の archive | 69 語 | 1 語 |

15 語の内訳は
`スキャン パラメタライズ ベースライン 一点 件追記 全部通 基準日
外部依存 新規分 既存分 直接確 直接見 観測 足場 速度`。
**「足場」は前例 0 件で必ず挙がる。**

造語を作っていない文書では 1〜3 語しか出ず、しかも「羽目」「事柄」
「具体例」のような普通の日本語だった。**挙がった語数そのものが目印に
なる。**

### 分かった限界

- **前例なし ＝ 造語ではない。** 同じ時点で「ゴールデンマスター」も
  前例 1 件しかなかった。一般に通用する専門用語でも、このリポジトリ
  では初出になる。`git grep` は候補を十数語に絞るところまでで、
  「一般に通用する語か」は人（担当）が判断するしかない。**判断する
  対象が十数語に減るのが、このやり方の値打ち**
- **機械で語を切ると屑が混ざる。** 形態素解析器（mecab・janome・
  fugashi）はどれも入っていない。正規表現で切ったので「件追記」
  「全部通」「直接確」「直接見」のような切れ端が 15 語のうち 4 語を
  占めた。**語を拾うのは担当（LLM）が読んでやり、`git grep` は前例の
  有無を答えるだけにする**
- **`writer.md` には既に「造語を使わない」と書いてある。** 書いてあっても
  止まらなかった。「足場」を書いたのは writer ではなく implementer
  だったため

## 決めたこと

**担当と hook の両方を使う。** 役割が重ならない。hook には「一般に通用
する語か」の判断ができず、担当は main が立て忘れたら動かない。

- **確認の担当を新しく作る。** 役割は、コミットに入る `.md` に出てくる
  呼び名を拾い、`git grep HEAD` で前例の有無を見て、**前例の無い語を
  全部挙げる**こと。一般に通用する語かどうかの見立ては添えるが、
  **文書は直さない**（直すかは main が決める。reviewer と同じ形）。
  **既知語リストは持たない**（一度指摘された語しか止まらず、次の造語が
  素通りするため）
- **hook には判断させない。** `git commit` を捕まえて、`.md` が入って
  いれば「確認の担当を立てたか」を促すだけにする
- **対象は、そのコミットに入る `.md` 全部。** 依頼書・archives・
  `CLAUDE.md`・README に加えて、**担当の報告ファイルも含める**
  （「足場」が入っていたのがそこなので、外すと今回の例を見逃す）
- **ゼロは狙わない。** 前例の無い語を挙げるところまでが担当の仕事で、
  見落としは残る

定義ファイルと hook を実際に作るのは **TODO-026**。定義が 6 個になり
`CLAUDE.md` の「3〜4 個に絞る」からさらに離れるので、そこで既存 5 個の
整理も併せて見る。
