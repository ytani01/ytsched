## きっかけ

システム手帳の使用感に近づけ、直感的に操作できるようにする。前は
前後 45 日（`DEF_DAYS`）を縦に連続して並べ、画面の端までスクロール
すると次を読み直していた。どこを見ているのかが分かりにくく、1 週間と
いう区切りも画面からは読み取れなかった。

もとは 1 つの項目だったが、3 つに分けた（2026-08-26）。左右のスワイプは
TODO-054、ヘッダと日付欄の手直しは TODO-055。ここは週表示の土台と
ゲージを受け持った。

## やったこと

### 週の範囲にした

`load_sched()` の通常モードの範囲を「`date` を含む週の月曜〜日曜」に
した。

```python
monday = date - datetime.timedelta(date.weekday())
date_from = monday
date_to = monday + datetime.timedelta(6)
```

検索モードの範囲（`SEARCH_MODE_MAX_DAYS` / `SEARCH_MODE_DAYS` /
`search_n` の打ち切り）は変えていない。検索結果は日付が飛び飛びで、
週の区切りに合わないため。

**テンプレートへ渡す `date` は、指定された日のまま月曜へ丸めていない。**
`main.html` の `class_blink`（表示の起点の日を光らせる）と `cur_day` が
これを見ているので、丸めると毎回月曜が光ってしまう。週を送ったときは
`moveToMonday()` が月曜を渡すので、そのときは月曜が光る。

### `--days` を消した

週表示にすると通常の表示に効かなくなり、残る用途は `date_range()` の
余白計算だけになった。そこは `SEARCH_MODE_MAX_DAYS`（1825）のほうが
常に大きく、実質使われない。**「渡せるのに効かない」オプションを
残さない**と決めて消した（着手時に利用者と決めた）。

消したのは `__main__.py` のオプション、`webapp.py` の `days` 引数と
`settings["days"]`、`handler.py` の `self._days`、`MainHandler.DEF_DAYS`。

### ゲージを週単位にした

変えたのは針に渡す値だけで、対数目盛りの仕組みも、ラベル（-30y〜+30y）
も、Python 側の `GAGE` もそのまま使っている。

| | 前 | 週単位にしたあと |
|---|---|---|
| 針の位置の元になる値 | `getTopDateString()`（画面最上部に見えている日） | 表示中の週の月曜 |
| 針を動かす仕掛け | スクロールのたびに `scrollHdr0` → `dispGage` | 読み込みのときに一度だけ |
| 基準線 `gage_r_base` | 今日 = 0 | 今週の月曜 = 0 |

`dispGage()` は渡された日を `mondayOf()` で月曜へ丸めてから、今週の
月曜との差を見る。**検索モードで飛び飛びの日（`date_from`）を渡しても
同じ関数で済む**ので、検索の有無で呼び分けなくなった。

針が週ごとに飛ぶので、CSS の `transition` で滑らせた。ただし
**`transition` を足すだけでは動いて見えない**（週送りはページの
読み直しで、`bottom` の初期値が `auto` なので補間が起きない）。
`sessionStorage` に直前の週を持ち、読み込み時にまずその位置へ
`transition` を効かせずに置いてから、次のフレームで今の週へ動かす形に
した（着手時に利用者と決めた）。

実測した針の位置（幅 412px）。今週は基準線とちょうど重なる。

| | 今週 | +1週 | +2週 | +3週 |
|---|---|---|---|---|
| `#gage_r` の `bottom` | 490px | 428px | 408px | 397px |

### `my.js` からスクロール追従を落とした

`getTopDateString()` / `scrollHdr()` / `scrollHdr0()` / `scrollHdrTimer` /
`scrollFlag` / `getDaysFromToday()` を消した。`moveToMonday()` の
「3 週先・2 週前が DOM にあるか見る」先読み判定も、週表示では前後の週が
DOM に無いので落として、常に `doGet()` する形にした。

`main.html` からは `scroll` イベントの登録と、使われなくなった hidden の
`date_to` を消した。

## 途中で見つけたこと

### ホームボタンが効かなくなっていた（利用者が見つけた）

**この項目で持ち込んだ退行。** 今日から離れた週を出しているとき、
ホームボタンを 1 回押すと**URL だけが今日に書き換わり、画面の中身は
前の週のまま**になっていた。

原因は `my.js` の `scrollToId()` で、**目的の要素が DOM にあるかを
見る前に、「1 画面に収まっている」というだけで `true`（＝スクロールで
用が足りた）を返していた**こと。呼び出し元の `scrollToDate()` は
これを成功とみなし、URL を積んだうえで `doGet()` を呼ばずに戻る。

前は 91 日ぶんを並べていたので `body_h <= win_h` はまず成り立たず、
この近道に入らなかった。週表示で 7 日だけになり、予定の少ない週では
1 画面に収まるようになったことで表に出た。

要素の有無を、画面に収まっているかより先に見る順番へ入れ替えて直した。
**順番に意味があることが読めるよう、理由をコメントに残した。**

**reviewer も verifier も捕まえられなかった。** verifier は
**今週を表示した状態から**ホームを押していたので、今日が DOM にあり
通ってしまった。依頼書に「今週へ戻る」としか書かず、**どこから戻るかを
指定しなかった**のが原因。この取りこぼしから TODO-056 を立てた。

### reviewer が見つけた 3 件

1. **`dispGage()` の `sessionStorage` が無防備だった。** Safari の
   Cookie ブロックなどで `SecurityError` を投げると、`onloadHdr()` の
   `body_h < win_h` 分岐で `visibility = "visible"` に届かず、
   **画面が白いまま止まる**。しかも**週表示にしたことでこの分岐に入る
   頻度が上がっている**。`try`/`catch` で包み、あわせて
   `visibility = "visible"` を `dispGage()` より先に移した
2. **`.my-gage-r-no-transition` がソース順で勝っているだけだった。**
   `.my-gage-r.my-gage-r-no-transition` にして詳細度で勝たせた
3. **ToDo の境界のテストが、曜日によって意図が薄まる。** 期限の日が
   表示中の週に入るかどうかが曜日で変わるため。対になっている 2 件を
   どちらも `day_block(body, today)` で見る形に揃え、
   「`todo_days` の境界で今日の欄に出るか・出ないか」の対比に
   なるようにした（対のもう片方は main が見つけた）

### テストが曜日に依存していた

implementer が `test_overdue_todo_is_shown_on_today` を直した。期限を
「3 日前」にして `body.count(TITLE) == 1` を見ていたが、週表示では
実行日の曜日によって「3 日前」が今週に入るかどうかが変わる
（木〜日なら 2 になって落ちる）。たまたま水曜に走らせていたので通って
いただけだった。

## テスト

`mise run fmt` / `typecheck` / `lint` / `test`（430 passed）。

足したもの（`tests/test_main_handler.py`）:

- 通常モードの範囲が `date` を含む週の月〜日ちょうどであること
- 月曜を指定したとき、その日が `date_from` になること
- 日曜を指定したとき、その週の月曜まで戻ること
- 年をまたぐ週（2025-12-29(月)〜2026-01-04(日)）でも 7 日ちょうどで
  あること

`tests/test_web.py` に `day_block(body, date)`（1 日分の欄だけを
取り出す）を足した。週表示では、期限が先の ToDo でもその日が週の範囲に
入っていれば欄に出るので、「今日の欄にだけ出る／出ない」を見るには
本文全体でなく欄だけを見る必要がある。

**ホームボタンの退行を捕まえるテストは足せなかった。**
`AsyncHTTPTestCase` は JavaScript を実行しないので、ブラウザ側の分岐の
順番は Python 側では原理的に捕まえられない。playwright を `pytest` へ
組み込むことになり、この項目の範囲を超えると判断した。この穴は
**TODO-056** として立てた。
