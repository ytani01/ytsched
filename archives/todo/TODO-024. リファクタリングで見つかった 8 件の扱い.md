# TODO-024. リファクタリングで見つかった 8 件の扱い

見込み: main = Sonnet 5 / effort medium、担当 = main のみ
実施: main = Opus 5 / effort high、担当 = main のみ

## きっかけ

TODO-021（挙動を変えないリファクタリング）の途中で、挙動がおかしそうな
箇所が 8 件見つかった。TODO-021 の中では直さず、現状のままテストに
書き留めてある。8 件の中身は
[`TODO-021. リファクタリング（挙動は変えない）.md`](TODO-021.%20リファクタリング（挙動は変えない）.md)
の「見つけたが直さなかった挙動」にある。

**この項目は決めるだけ**で、直すのは TODO-027・TODO-028。

## 調べたこと

決める前に、一時ディレクトリでアプリを起こして 500 になる入力を実際に
叩いた。**8 件のリストに書かれていた 2 件より広く、一部は次のリクエスト
でも直らない**ことが分かった。

| 入力 | 1 回目 | そのあとの素の GET | `Conf.cgi` |
|---|---|---|---|
| `search_n=`（空） | 500 | 200 | `SearchN` が空で残る（読むときに既定値へ落ちる） |
| `search_n=abc` | 500 | **500** | `SearchN=abc` が残り、以後ずっと 500 |
| `todo_days=abc` | 500 | **500** | `ToDo_Days=abc` が残り、以後ずっと 500 |
| `year=abc`／`day=0`／`month=13` | 500 | 200 | 保存されない |
| `date=abc`／`cur_day=abc` | 500 | 200 | 保存されない |

リストに無かったものが 3 つある。

- `todo_days` が数字でないときも 500 になる
- `date` / `cur_day` が ISO 8601 の日付でないときも 500 になる
- **`search_n` / `todo_days` に数字でない値を入れると `Conf.cgi` に残り、
  以後トップページも開けなくなる。** TODO-021 に「次のリクエストでは
  既定値へ落ちて画面は直る」とあるのは `search_n=`（空）だけの話で、
  空でない不正な値は直らない

## 決めたこと

### 1. 不正な入力で 500 になる件（TODO-027 へ）

- **数字・日付にならない値は既定値へ落として、画面は出す。**
  ログに警告を出す。TODO-012 で決めた「不正な正規表現はその条件を無視
  して全件を出す」と同じ扱いにする。単一ユーザなので、エラー画面より
  見えるほうが使いやすい
- 対象は `search_n`・`todo_days`・`year`/`month`/`day`・`date`・
  `cur_day` の 5 か所
- **不正な値は `Conf.cgi` へ保存しない**（`int()` に通る値だけ保存する）。
  読むときに既定値へ落とすだけでは、`Conf.cgi` に不正な値が残ったまま
  になる。一度踏むだけで 500 が返り続ける経路をここで断つ

### 2. 画面の使い勝手（TODO-028 へ）

- **`filter_str` は空で送れば解除する。** `search_str` と揃える
  （`empty_is_given=True` にする）。入力欄を空にして送るのが自然な
  解除の操作
- **`filter_str` は小文字にしてから保存する。** `set_conf()` を
  `.lower()` のあとに回し、`Conf.cgi` も画面も `abc` で揃える。照合は
  もともと小文字でしているので、絞り込みの結果は変わらない
- **`sde_align` は今のまま**（毎回 `top` に戻る）。表示位置はその場限りの
  切り替えでよく、覚える必要は無い

### 3. 些細な 2 件と速度（TODO-028 へ）

- `detail` の `〆` 行に残る余分な空白を直す
- どこからも使われていない `MainHandler.COOKIE_TODO_DAYS` を消す
- 検索モードの 1825 日スキャンは、**挙動を変えずに速くする**。
  さかのぼる範囲（`SEARCH_MODE_MAX_DAYS`）は今のままで、ファイルの
  無い日は開きに行かずに飛ばす。1 件も当たらないうちだけ 1825 日
  さかのぼるのは古い予定を拾うための設計なので、範囲そのものは縮めない
