## きっかけ

「ミニマップ（ミニカレンダー）の領域で左右にスワイプ（ドラッグ）したら、
1 ヶ月単位で移動するようにする。移動先の曜日は月曜にする」という利用者
からの依頼。

## やったこと

`src/ytsched/webroot/static/js/swipe.js`・`week.js`・`nav.js`（ヘッダの
コメント一覧のみ）を直し、`tests/test_browser.py` にブラウザテストを
4 件足した。

### swipe.js

これまで週送りのスワイプ・ドラッグの始点だけを覚えていた
`touchStartHdr`/`mouseDownHdr` に、始点がミニカレンダーの表
（`.my-mini-cal`）の上だったかどうかを `swipeMiniCal` という変数で
覚えさせた。`swipeDragTo()`（追従表示の判定）と `swipeFinish()`
（離したときの確定）に分岐を足し、ミニカレンダーの上で始まった
スワイプ・ドラッグは、週送りの追従アニメーション（`translateX`）を
せず、しきい値を超えて離したときに `week.js` の `moveActiveMonth()`
を呼ぶようにした。検索モードでは `.my-mini-cal-row` 自体が
`{% if not search_mode %}` に入っていて DOM に無いので、
`swipeMiniCal` と検索モードの分岐（`search_date_to`）が同時に成り立つ
ことは無い。

### week.js: moveActiveMonth()

**最初の実装（reviewer が不具合を発見）:** `activeMonday` を
`Date.setMonth()` で月単位にずらしてから、`mondayOf()`（gauge.js）で
その週の月曜へ丸める、という 2 段の処理で組んだ。ところがこの丸めが、
月をまたいだ直後の曜日が週の前半（日〜木寄り）だと月境界を越えて
元の月（時には 2 ヶ月前）へ押し戻してしまうことが、reviewer の検算
（2021〜2030 年の「月の第 1 月曜」120 件のうち、前進 42 件・後退 71 件
で発生）で分かった。まさにテストに使っていた 2026-03-02（3 月の第 1
月曜）自体がこのケースで、左スワイプ（次へ）をしても 3 月に留まって
しまっていた。

**直した設計:** 「``activeMonday`` がその月の何番目の月曜か」を
`mondayDaysInMonth(year, month)`（新規、その月に実在する月曜の日を
古い順に返す）で求め、月をずらした先の月でも同じ番目の月曜へ移る
ようにした。ずらした先の月の月曜の数がそれより少なければ（4 週の月
から 5 週の月へ動いたときなど）、その月の最後の月曜に留める。
`targetDay` は必ず `mondayDaysInMonth()` が返した「その月に実在する
月曜の日」なので、結果の月が「ずらした先の月」から外れることは
構造上あり得ない。

移動そのものは、月間ミニカレンダーのセルをタップしたときと同じ
`scrollToDate()`（nav.js）に乗せた。読み込み範囲にあればそのまま移り、
無ければ読み直す、という既存の分岐をそのまま使っている。

## テスト

- `mise run lint`（fmt / ruff / basedpyright / mypy / eslint）が通る
- `uv run pytest tests`（560 件、新規のブラウザテスト 4 件を含む）が
  通る
- 新規のブラウザテスト 4 件（`tests/test_browser.py`）:
  タッチでの前進・後退、マウスドラッグでの前進、しきい値未満の動きは
  従来どおりセルのタップとして扱われること。**実装の内部ロジック
  （何番目の月曜かという計算）を Python 側で再現するのではなく、
  要件そのもの（「表示の年月がちょうど 1 ヶ月分だけ動く」「移動先の
  曜日が月曜になる」）だけを検証する**ように書いた
  （`_expected_month()` は年月だけを計算し、日には触れない）。
  1 回目の実装では、実装と同じ計算をテストが再現していたために
  上記の不具合をテストで検出できなかった、という反省から
- 念のため、2021〜2030 年の全ての月曜・両方向（1044 件）を実際の
  ブラウザ（chromium）で `moveActiveMonth()` を直接呼んで確認
  （不具合 0 件）。reviewer も同じ考え方で 2000〜2040 年・4,280 通りを
  Node で検算し、不具合 0 件を確認している
- 一時ディレクトリ（実データ非汚染）でアプリを起動し、verifier が
  playwright で実機確認。ミニカレンダーでのドラッグ → 月送り、
  ミニカレンダー以外でのドラッグ → 週送り（退行なし）、しきい値未満の
  タップ → 通常の日移動、検索モードのスワイプへの影響が無いこと、
  いずれも問題無し

以上は main（実装）・reviewer（コードレビュー、2 回）・verifier
（別セッションでの実機確認）でそれぞれ確かめた。reviewer の 1 回目の
指摘（月境界の丸めの不具合）は上記のとおり直し、2 回目の再確認で
新たな指摘は無かった。verifier からの指摘も無かった。
