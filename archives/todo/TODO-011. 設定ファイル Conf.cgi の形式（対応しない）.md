# TODO-011. 設定ファイル `Conf.cgi` の形式（対応しない）

見込み: Sonnet 5 / effort low（サブエージェントなし）
実施: Opus 5 / effort high（サブエージェントなし）

## きっかけ

設定を datadir 内の `Conf.cgi` にタブ区切りで置いている
（`ToDo_Days`、`FilterStr`、`SearchStr`、`SearchN`）。データファイルと違って
利用者が手で書くものではないので、形式を変えても互換の問題は小さい。
TOML 化するか現状維持かを決める項目として立てた。

## やらないと決めた理由

**現状維持。タブ区切りのまま変えない。**

調べて分かったこと:

- **アプリ自身が書いている。** `HandlerBase.set_conf()` → `save_conf()` で
  Web UI からの操作を書き戻している。利用者が手で編集するファイルではない
- キーは 4 つだけで、値はすべて文字列
- `HandlerBase.__init__` の中で読んでいるので、**リクエストのたびに読み直している**

判断の決め手:

- **TOML は書き込みが標準ライブラリに無い。** 読みは `tomllib` で足りるが、
  書くには `tomli-w` などの依存が増える。この設定はアプリが書くので、そこが効く
- **TOML の利点（人が読み書きしやすい）が活きない。** 手で触らないファイルなので、
  形式を人間向けにする理由が無い
- JSON なら標準ライブラリだけで読み書きでき、自前パーサも消せる。
  ただし既存の `Conf.cgi` からの移行処理か、設定を捨てる割り切りが要る
- 形式を変える動機として残るのは `load_conf()` の `ValueError`
  （タブの無い行で落ちる）だが、**これは TODO-005 で直す**。
  形式を変えなくても解決する

利益が小さく、移行の手間と依存の増加が残るので、変えない。

将来この判断を蒸し返すとしたら、設定項目が増えて値の型が
文字列だけで収まらなくなったとき。そのときは TOML より、
依存の増えない JSON を先に検討する。

## テスト

コードを変えていないので無し。
