## きっかけ

TODO-179 で直したはずの症状が残っていた。

ドラッグ先が先読みの範囲の外だと、`scrollToDate()` は `doGet()` で
ページを読み直す。読み直した先では針の `style.left` が空なので、
TODO-179 で足した「針が既に位置を持っているか」の分岐を通らない。
`sessionStorage` に残っているのはドラッグ開始前の週（遠くへ動かすと
追従タイマーが動かず `dispGauge()` が呼ばれない）で、そこから目的地へ
補間する TODO-049 の演出がそのまま出る。

playwright で実測した境界:

| 表示 | ドラッグ量 | 離したあとの `style.left` |
|------|------|------|
| 週間 | +4w | 変化なし |
| 週間 | +5w | `''` → `50%` → `60.74%` |
| 月間 | +150日 | 変化なし |
| 月間 | +1y | 変化なし |
| 月間 | +3y | `''` → `50%` → `83.59%` |

境界の差は先読みの広さ（`LoadWeekPages=4` / `LoadMonthPages=2`）の差。
ゲージの目盛りは `-30y` 〜 `+30y` なので、普通に使えばほぼ必ず読み直しの
経路に入る。**TODO-179 で直っていたのは、目盛りでいえば `±1w` の内側
だけだった。**

根は、針の出発点をどう決めるかが 3 か所に散っていたこと。

1. `sessionStorage` の「直前に見ていた週」（TODO-049）— ページの
   読み直しをまたいで残る唯一の手がかりだが、意味は「見ていた週」で
   あって「針をどこから動かすか」ではない
2. 針の `style.left`（TODO-179 で足した分岐）
3. ドラッグ中の針の位置 — 読み直しで消える

ドラッグして飛ぶときの本当の出発点は (3) なのに、読み直しで消えて (1) が
代わりに使われていた。

## やったこと

- **`sessionStorage` に持たせる値の意味を変えた。**
  `ytsched_gauge_monday`（直前に見ていた週）→ `ytsched_gauge_start`
  （次にページを読み込んだとき、針を置き始める位置）。
  `getGaugeMonday()`/`setGaugeMonday()` も改名した
- **`gaugeBarPointerUpHdr()` が、ページを読み直す前に離した位置の週を
  出発点として書く。** 読み直した先では出発点と目的地が同じになり、
  針は動かずにそこへ出る。読み直しにならなければ、そのあとの
  `dispGauge()` が同じ値で上書きする
- **`dispGauge()` の分岐を、`style.left` を見る形からフラグに変えた。**
  モジュール内に `gaugePlaced` を置き、ページを読み込んでから初めての
  呼び出しのときだけ出発点を使う。2 回目からは針が今いる位置から
  動かす。`style.left` で読み直し直後を当てるのは間接的で、今回の
  見落としの元でもあった

週送りは今まで見ていた週を出発点として書くので、TODO-049 の演出は
そのまま残る。

## テスト

- `tests/test_browser.py` に 2 件足した。
  `test_gauge_drag_needle_does_not_pass_this_week_on_reload`（週間、
  +5w）と `..._on_reload_month`（月間、+3y）。ページの読み直しを
  またぐので、`add_init_script()` で仕込んだ `MutationObserver` の
  記録を `sessionStorage` へ書き、読み直したあとにまとめて読む
- **直す前のコードで走らせて 2 件とも落ちること、直したあとに通ることを
  両方確かめた**（TODO-179 の振り返りに書いたとおり）
- verifier が `mise run lint` と playwright での実測を担当した。
  週間 +5w・月間 +3y は 50% を経由せず移り先の位置に一致、週間 +4w は
  針が動かない（TODO-179 の挙動を維持）、`?date=X` → `?date=Y` の
  読み直しでは X から Y へ動く（TODO-049 の演出は健在）、ホームボタン・
  週送り・月間表示は変わらず、console エラーは 0 件
