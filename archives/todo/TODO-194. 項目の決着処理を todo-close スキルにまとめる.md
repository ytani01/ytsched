| 実施 | Opus 5 / effort high | main + verifier |

|------|--------|--------|--------|----------------|-----------|

| verifier | Sonnet 5 | medium | 2,403 | 44,528 | 15% |
| 合計 |  |  | 16,942 | 94,775 | 概算 $1.5 |

- どちらも定義のまま。verifier は `.claude/agents/verifier.md` の
  `model: sonnet` / `effort: medium`
- 立ててから着手まで空いた（TODO-195・196 が間に入った）ので、
  `--since '2026-09-07 07:05:24'`（TODO-195 の決着コミットの時刻）で切った

## きっかけ

決着のたびに手でやっている手順が、完全に決まっていた。`TODO.md` の節を
`archives/todo/` へ移す、2 つの表を作る、`token-usage.py` を叩いて埋める、
目次と残件数を直す、分担の振り返りを書く。毎回同じなのに、書式は
`~/.claude/CLAUDE.md` と（TODO-196 で作った）`todo-workflow` skill に
散っていて、表の形がぶれていた。

手順をスキルに持たせれば形がぶれない。`--since` を渡す判断（立ててから
着手まで空いた項目）の説明も、同じ場所に置ける。

## やったこと

### 置き場所を `~/.claude/skills/` にした

項目を立てたときは `.claude/skills/todo-close/` と書いていたが、
**`~/.claude/skills/todo-close/SKILL.md`（ユーザー全体）** に置いた。
決着の手順はどのプロジェクトでも同じで、進め方の規則は
`~/.claude/CLAUDE.md`、書式は `~/.claude/skills/todo-workflow/` にある。
ytsched 固有の事情（`mise run tokens`）は、スキル側では
「プロジェクトに `mise run tokens` があればそちらでもよい」と 1 行触れるだけにした。

### 手順だけを持たせた（書式は書かない）

`SKILL.md` は 9 つの手順。frontmatter は
`disable-model-invocation: true`（利用者が `/todo-close TODO-NNN` で起動する）と
`argument-hint: TODO-NNN [--since '<日時>']`。

1. 決着させてよいかを確かめる（チェックボックス、やらないと決めた項目の扱い）
2. `todo-workflow` skill を読む
3. `archives/todo/` のファイルを作る（骨格とファイル名の付け方）
4. 2 つの表を埋める（テンプレート同梱）
5. トークンを集計する（`--since` の見分け方）
6. `TODO.md` を更新する（4 か所）
7. サブエージェントを使ったときの追加分
8. コミットする
9. `/clear` を勧める

**表の列や `cache_read` を入れない理由といった書式は、スキルに書いていない。**
手順 2 で `todo-workflow` skill を読ませる。二重に持つと片方だけ古くなる。

手順 6 だけは、忘れやすい 4 か所（節の削除・目次の先頭・残っている番号・
決着件数）を数え方まで書いた。決着件数は
`grep -c '^- \[\*\*TODO-' TODO.md` で数え直す。

### `docs(todo):` で決着させない、を書き加えた

この項目の集計中に見つけた。`token-usage.py` の終点は
**「`docs(todo):` 以外で `（TODO-NNN）` を含むコミット」**なので、決着の
コミットを `docs(todo):` で始めると終点が見つからない。直前の TODO-195 が
実際にこれで、`--list` に「(未完了)」と出る。手順 8 に注意として入れた。

### 手順 6 を、誤検出の後始末で書き直した

verifier の「TODO-073 のリンク切れ」の報告を確かめたところ、切れていな
かった。同じ思い込み（リンク先に `( )` を入れられない）が手順 6 にも
書いてあったので、**「釣り合った `( )` はそのままでよい」**に直し、
**「足したリンクが実在するか、貪欲マッチで照合する」**を手順に足した
（4 か所 → 5 つ）。

### `/todo-open` は作らなかった

立てたときの「決めること」どおり、まずは決着側だけにした。使ってみてから決める。

## 確かめたこと

**書いたスキルを、この TODO-194 自身の決着にそのまま使った。**
手順 1〜9 を順に辿り、途中で足りなかったところ（上の `docs(todo):` の件）は
その場でスキルに書き足した。

**ただし `/todo-close` として起動したわけではない。** Claude Code は
スキルを起動時にしか読まないので、この会話では `SKILL.md` を直接読んで
手順どおりに進めた。スラッシュコマンドとして認識されるかは、
利用者が再起動してから分かる。

verifier に、できあがった `archives/todo/` のファイルと `TODO.md` が
`todo-workflow` skill の書式に合っているか、スキルの各手順が書いたとおりに
再現できるかを確かめさせた。報告は
`archives/agents/TODO-194/verifier-report.md`。

## 分担の振り返り

- **verifier は、TODO-194 の変更そのものには不備を見つけなかった。**
  代わりに、目次 194 件のリンクを機械的に照合して **TODO-073 の
  リンク切れ**（ファイル名と目次の綴りが違う）を見つけた。これは
  TODO-073 のときからの既存の不具合で、今回の diff には入っていない。
  「実際に叩いて確かめる」担当を分けた効果は、`token-usage.py` の
  `--since` 付き実行と `grep -c` の照合、frontmatter の 2 つのキーが
  公式プラグインに前例があることの確認に出た
- **verifier は誤検出を 1 件出した。** 目次 194 件のリンクを照合して
  「TODO-073 がリンク切れ」と報告したが、実際には切れていなかった。
  照合スクリプトが URL を最初の `)`（`「(c)` の閉じ括弧）で切っており、
  CommonMark が釣り合った括弧を許すことを踏まえていなかった。
  **報告をそのまま項目にせず、main が貪欲マッチで照合し直して潰した**。
  同じ思い込みが `SKILL.md` の手順 6（「`( )` は含めない形にする」）にも
  入っていたので、そちらも直して、照合するなら貪欲マッチで取ることを
  手順に加えた
- **見込み（writer + verifier）とは食い違い、着手時に main + verifier へ
  変えた。** 書く中身が main 自身の手順そのもので、writer に渡すには
  結局その手順を全部書いて渡すことになる。文章を書く担当を分けても、
  渡す文章を先に書くなら意味が無い
- **次に同じ規模（スキルや定義ファイルを 1 本書く項目）をやるなら、
  main + verifier で組む。** ただし verifier への依頼には
  「実際に叩けるコマンドを 1 つずつ試す」と「機械的な全件照合」を
  必ず名指しで入れること。今回の収穫はどちらもそこから出た。
  書式の目視だけを頼むなら分ける必要は無い

## 残ること

- **`/todo-close` が認識されるかは、利用者が Claude Code を再起動してから
  分かる。** 手順の中身は上のとおり実地で確かめてある
- **`/todo-open`（立てる側）は作っていない。** 決着側を何回か使ってから決める

スキルの実体は `~/.claude`（`dotfiles-claude`）側。このリポジトリで変えたのは
`TODO.md` と `archives/` だけ。
