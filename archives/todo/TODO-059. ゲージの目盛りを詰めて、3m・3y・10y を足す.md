## きっかけ

TODO-058 でヘッダに出した横ゲージを使っていて、利用者が
**「`-1w` と `+1w` の間隔が開きすぎている」**と言った（2026-08-26）。

目盛りの位置は対数で決めている。日数が小さいところほど間隔が広がるので、
7 日は中心から 10.9% の位置になる。左右対称に置くため、`-1w` と `+1w` の
間だけが 21.8% 空いていた。ほかの目盛りの間隔は 7.6〜18.3% で、中央だけが
飛び抜けて広い。

式の中の `0.6`（日数が 0 のときに対数が計算できなくなるのを避けるため
に足していた値）を小さくしても
10.9% → 10.5% にしかならず、効かなかった。

## やったこと

### 1. 式を変えた

```
今まで:   log10(日数 + 0.6)     / log10(30年 + 0.6)
これから: log10(1 + 日数 / K)   / log10(1 + 30年 / K)
```

`K`（`DAYS_GAGE_K`）は中心の近くをどれだけ詰めるかを決める。大きいほど
詰まる。**利用者が最初 5 を選び、目盛りを増やしたあとで 10 にした。**

`days == 0` を特別扱いして 0 を返していた分岐は消した。新しい式は 0 を
入れるとそのまま 0 になる（今までの式は 0 に近づけると -2.7% へ向かうので、
そこに小さな段差があった）。

Python（`main_handler.py` の `days2x_percent()`）と JavaScript
（`my.js` の `days2xPercent()`）の両方を、同じ式・同じ定数にそろえた。

### 2. 目盛りを 8 個から 14 個に増やした

利用者から「`±6m` と `±10y` も入れたい」と言われた。**`6m` を入れると、
幅 412px 以下で `+6m` と `+1y` のラベルが重なる**（実測で -1.3px）。
`6m` と `1y` は 2 倍しか離れておらず、対数の上では必ず近くなるため、
`K` をどう変えても 4〜5% の間隔にしかならない。

そこで「`1m` と `1y` の中間は何ヶ月か」を逆算したところ **3.6 ヶ月**
だった（対数目盛りなので、1 と 12 を掛けて平方根を取った値
√12 ≒ 3.46 の近くになる）。
利用者が `6m` をやめて `3m`・`3y`・`10y` を選んだ。

片側 `1w`・`1m`・`3m`・`1y`・`3y`・`10y`・`30y` の 7 つ。
**1 → 3 → 10 の並びは対数の上で等間隔になる**ので、目盛りの間隔が
6.2〜9.4% に揃った。

### 3. K を 5 から 10 にした

利用者が「±1w の間隔をさらに狭めたらどうなるか」と聞いた。`K` を上げると
中央は詰まるが、**`1w` と `1m` の間も一緒に詰まる**ので、そこが先に限界に
なる。412px と 360px で実際に描かせて測った。

| K | `-1w`〜`+1w` | いちばん狭いところ（412px） | 同（360px） |
|---|---:|---|---|
| 5 | 11.4% | `+1m`〜`+3m` 5.0px | `+10y`〜`+30y` 1.4px |
| 8 | 8.7% | `+1m`〜`+3m` 5.2px | `+1m`〜`+3m` 1.8px |
| **10** | **7.6%** | **`+1w`〜`+1m` 4.4px** | **`+1w`〜`+1m` 1.1px** |
| 15 | 5.8% | `+1w`〜`+1m` 1.7px | `+1w`〜`+1m` 1.1px 重なる |
| 20 | 4.8% | `+1w`〜`+1m` 0.4px 重なる | 2.9px 重なる |

**10 が、幅 360px で重ならない上限。** これより上げるときは、実際に
描かせて確かめること。定数のところにも同じことを書いてある。
