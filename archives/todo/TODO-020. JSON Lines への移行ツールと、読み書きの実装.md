## やったこと

### 読み書きを JSON Lines に

- `SchedDataFile` のパスを `{年}/{月}/{日}.jsonl` / `ToDo.jsonl` に。
  文字コードは utf-8 のみ（`utf-8` → `euc_jp` と試すのをやめた）
- `load()` はバイナリで読んで `split(b"\n")` で切り、**行ごとに**
  デコード・パースする。`str.splitlines()` は使わない（U+2028 でも
  切ってしまい、`detail` に U+2028 を含む 1 件が 2 行に割れる。実データに
  1 件あった）
- 読めない行はその行だけ飛ばして警告し、ファイル全体は捨てない
- `htmlstr2text()` / `text2htmlstr()` を削除。`detail` は素のテキストの
  まま持ち、読み書きで文字列を変換しない

### 判定・検索の正規化

モジュール関数 `normalize()`（全角括弧を半角に、小文字に）を足し、
`is_important()` / `is_canceled()`、`get_sortkey()`、`search_str()` の
3 か所だけで使う。**保存する文字列は変えない。** `is_todo()` と
`is_holiday()` は変えていない。

これで `（重要）打合せ` が、入力直後と再読み込み後で判定が食い違う状態が
解消した（どちらでも重要と判定される）。挙動が変わる点は意図したもので、
テストで押さえてある。

### 飛ばした行の書き戻し

reviewer の指摘から入れた。読み込みで飛ばした行を**生のバイト列のまま**
覚えておき、次の `save()` でファイルの末尾へ元のバイトのまま書き戻す。
保存をくり返しても壊れた行が失われない。

ただし**空行（空白だけの行を含む）は書き戻さない**。失うデータが無く、
書き戻すと警告が出続けるため。判定は `SchedDataFile.is_empty_line()` に
まとめてある。

旧形式では「壊れた行があるファイルで操作を 2 回すると元のデータが消える」
経路があった（`docs/data-format.md` に実測を残してある）。行ごとに
切り分けるだけだと形を変えた同じ経路が残るので、書き戻しで塞いだ。

### 移行ツール `ytsched migrate`

CLI のサブコマンドとして足した（本体は `src/ytsched/migrate.py`）。
`uv tool install` したコマンドからそのまま使えるようにするため。

- 対象は `{年}/{月}/{日}.cgi` と `ToDo.cgi` だけ
- 変換は `docs/data-format.md` の「変換の手順」1〜6 のとおり
- 元の `.cgi` は消さない。既に `.jsonl` があるファイルは警告して飛ばす
- 変換できない行は捨てずに `--error-file` へ書き出す
- `--dry-run` で件数だけ数える。対象が 0 件なら警告する

### 文書

`CLAUDE.md` の「これは何か」「データモデルの勘所」「コマンド」を新形式に
合わせて書き直し、`docs/data-format.md` の状態・壊れた行の扱い・移行ツール
の使い方を実装に合わせた。形式の決まりは `docs/data-format.md` が置き場所
で、`CLAUDE.md` からは参照するだけにしてある。
