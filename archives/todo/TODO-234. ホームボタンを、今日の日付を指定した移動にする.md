## きっかけ

ホームボタンのダブルクリックで、今週の月曜日の欄が点滅した。`reloadHome()` が
`date=<月曜日>` を POST し、リダイレクト先の `?date=` を TODO-233 の点滅が拾っていた。

## やったこと

利用者が決めた要点は「日付を指定されたら点滅」「ホームボタンは今日の日付を指定した移動」の
2 つで、ほかは変えない。

- ホームボタン（通常画面のシングル・ダブル、検索画面の 1 回目・2 回目）とキーの `Home` は、
  今日を日付に指定して移動する。位置は日付指定と同じ（今日を上端に。`"top"`）
- 読み直す経路の点滅は、TODO-233 の `?date=<今日>` がそのまま拾う。読み直さない経路
  （シングルクリック、キーの `Home`）は、移動のあと `ytsched.flashDate()` を呼ぶ。
  `flashUpdated()` の点滅の付け方を `flashEl()` / `flashDate()` に切り出して使い回した
- ホーム専用の位置合わせ（`sde_align` の `"home"`。月曜日を上端に、今日がはみ出すなら今日の
  下端に。TODO-105、TODO-199）をやめ、`nav.js` の `scrollToId()` の分岐と
  `reloadHome()` の `sde_align: "home"` を消した。`mondayOf` とサーバの `sde_align` の
  引き継ぎはほかが使うので残した
- テストを新しい動きに合わせ、`_wait_for_reload()` で読み直しが済むのを待つようにした
- `src/README.md`、`docs/UsersGuide.md`、依存コメントを直した

途中、月曜日を上端にする位置合わせを保つ方式で 2 回作った（`e3375c5`、`d9c3601`、`4720cf5`）。
レビューで 2 回続けて、F5 や戻る/進むでの位置が変わる不具合が出たのでやめた。正味の差分は
`git diff 534930a 0b7411d`。

## 分担の振り返り

- **見つけたもの:** reviewer は 1 回目と 2 回目で、月曜日基準の方式が F5・戻る/進むの位置を変えることを
  見つけ、方式をやめるきっかけになった。3 回目でテストの待ち合わせの弱さを見つけた。verifier は
  3 通りの壊し方でテストが落ちることを実測した。implementer は「F5 で月曜日が点滅するのは避けられない」
  「検索画面の 1 回目では今日が出ない」と、方針の無理を止まって報告した
- **見込みと食い違った理由:** 担当の組み方は見込みどおりだが、作り直しが 3 回重なり、implementer の分が
  40% まで膨らんだ。原因は main の側にある。利用者の「今日に日付指定して移動し、今日が点滅する方がいい」を、
  元の位置合わせを保つ案を推奨にして聞いたため、専用の仕組みを足す方向へ進んだ。方針の連絡が担当の作業中に
  行き違い、古い方式のコミット（`4720cf5`）もできた
- **次に同じ規模なら:** 方針を聞いたら、既存の仕組みに乗せるだけの最小の差分（ここでは「渡す日付を今日にする」）を
  まず項目に書き、それを推奨にする。依頼文にも「足してよい処理はここだけ」と最初から書く。方針が途中で変わったら、
  担当に追加の指示を送らず、止めてから頼み直す。`model-check.md` の判定は 3 件とも「見合う」で、
  モデルと effort はこのままでよい
