## きっかけ

利用者から「左端のゲージの針（▶）の位置が内側にずれている」。

TODO-040 で Font Awesome を 5.6.1 から 7.3.1 へ上げた直後で、それまでは
正しい位置に出ていた。

## 原因

**Font Awesome 7 が、すべてのアイコンに `width: var(--fa-width, 1.25em)` と
`text-align: center` を付けるようになった。** 5.6.1 では、この 2 つが効くのは
`.fa-fw`（fixed width）を付けたときだけだった。

針の `fa-caret-right` は字面（グリフが実際に描かれる範囲）の幅が 0.5em しか
ないので、1.25em の箱の中央に置かれると、左に
`(1.25 - 0.5) / 2 = 0.375em` の余白が入る。`.my-gage` は
`font-size: large`（18px）で `fa-2x` なので 36px、余白は約 13.5px になる。
これが「内側へ寄って見える」の正体。

基準線の `fa-grip-lines`（幅 0.875em）も同じ理由で約 2.5px ずれていた。

**ずれた分だけ `left` の値をずらす案は採らなかった。** ずれる量が文字の
大きさに比例するので、`font-size` を変えるたびに合わせ直しになる。

## やったこと

分担と、その理由は
[archives/agents/TODO-042/README.md](../agents/TODO-042/README.md)。

### 1. 箱の幅をもとに戻す（`my.css`）

```css
.my-gage-text {
    display: inline-block;
    transform: translate(0%, 50%);
    /* Font Awesome 7 はアイコンの幅を 1.25em に固定して中央へ寄せる。
       ゲージは left で位置を決めているので、もとの幅に戻す (TODO-042) */
    --fa-width: auto;
}
```

FA 7 が用意している変数に `auto` を入れるだけで、箱が字面の幅に戻る。
**FA の CSS そのものは触っていない**（同梱しているファイルなので、上げ直す
たびに当て直しになる）。

対象は `.my-gage-text` に絞った。メニューバーやボタンのアイコン 30 か所ほども
1.25em の箱になっているが、そちらは位置を決め打ちしていないので実害が無い。

### 2. 針の左端を画面の左端に合わせる（`my.css`）

1 の時点で針は元の位置（`left: 1px`）に戻ったが、利用者から「針の左端を
x = 0 に」との指示があり、さらに 2 つ足した。

```css
.my-gage-r {
    left: 0px;
    opacity: 0.2;
}

/* fa-caret-right の字面は、幅 0.5em のうち左から 65/512em のところから
   始まる。針の左端を画面の左端 (x = 0) に合わせるため、その分を戻す
   (TODO-042) */
.my-gage-r .my-gage-text {
    transform: translate(-0.127em, 50%);
}
```

`fa-caret-right` は、字面の幅 0.5em の中でも左に `65/512em ≈ 0.127em` の
余白（left side bearing）を持っている。`left: 0px` にするだけでは、その分
だけ内側に残る。`transform` で戻すと、実測でも三角形の左端がちょうど
x = 0 に乗った（下記テスト）。

### 3. 基準線の縦位置（`main.html`）

```
-     elGageRBase.style.bottom = `${centerY}px`;
+     // FA 7 でグリフの実寸が変わり、同じ bottom では針と基準線の
+     // 重なり方がずれる。9px は実機で見て合わせた値 (TODO-042)
+     elGageRBase.style.bottom = `${centerY - 9}px`;
```

針と基準線が重なったときの見え方を、**利用者が実機で見て合わせた**。
FA 5 と FA 7 ではグリフの実寸（字面の高さ）が違うので、同じ `bottom` でも
重なり方が変わる。

`9` という数字の出どころがコードから読めないので、TODO-041 と同じように
その場にコメントを置いた。

## テスト

**テストは足していない。** 変えたのは CSS 3 か所とテンプレートの JavaScript
1 行で、Python 側のテストからは触れない。

verifier に 3 回確かめさせた
（[verifier-report.md](../agents/TODO-042/verifier-report.md)）。
どの回も、`--datadir` に一時ディレクトリを指定した別ポートのサーバを 2 つ
立てて、旧版と新版のスクリーンショットを撮って比べている。

- **1 回目（`--fa-width: auto` だけの状態）** — `getBoundingClientRect()` で
  `#gage_r` の幅が 45px から 18px に戻り、`left` は 1px のまま。画面全体を
  `compare -metric AE` で比べると、違う画素は 412 幅・740 幅とも 480 個で、
  座標を調べると**すべてゲージの領域（x: 3〜32、y: 1904〜2025）に収まって
  いた**。他は 1 画素も変わっていない
- **2 回目（`left: 0px` と `translate(-0.127em, ...)` を足したあと）** —
  スクリーンショットを PIL で直接読み、三角形のある 20 行すべてで
  `leftmost_nonwhite = 0` かつ色が一定（`rgb(208,208,208)`）だった。
  **x = 0 で本体の階調が既に始まっている**ので、左端が画面の外で切れて
  いるのではなく、ちょうど乗っている
- **3 回目（針と基準線の重なり）** — 比較相手を `e146a11^`（FA 5・
  Bootstrap 4.5 の一式、利用者が「正しい」と言っている状態）にして、
  `dispGage(今日)` を呼ばせて針を基準線に重ねた。三角形の右端から `＝` が
  はみ出す量は、FA 5 が約 4〜5px、今回が約 1px

後始末で `main.html` にコメントを足したあと、runner に `mise run lint` と
`mise run test` を走らせた（[runner-report.md](../agents/TODO-042/runner-report.md)）。
`ruff format` / `ruff check` / `basedpyright` / `mypy` とも通り、
テストは **418 件 pass**。

**`centerY - 9`（上記 3）は、この 3 回のどれにも入っていない。** 3 回目の
時点では基準線の `bottom` は旧版と完全に一致していた。実機で見て合わせた
変更なので、verifier には確かめさせていない。

### 撮り方について（verifier の申し送り）

一覧の HTML を静的化してスクリーンショットを撮るとき、
`window.addEventListener('load', onloadHdr);` を丸ごと消すと**ゲージの
縦位置が設定されず、針が画面外へ消える**。`onloadHdr` の後半（実際に
スクロールする部分）だけを止めて、前半の `bottom` を決める処理は走らせる
必要がある。静的サーバでは `doPost()` の送り先が無いので、スクロールを
走らせると再帰的に発火してタイムアウトする。

## 次に同じことをするときの申し送り

- **Font Awesome 7 は、すべてのアイコンを 1.25em の箱に入れて中央へ寄せる。**
  位置を決め打ちしている場所では `--fa-width: auto` で箱をもとに戻す。
  5.x からの移行で黙って位置が変わるのはこれが原因
- **アイコンの字面には、箱の中でも左右の余白（left side bearing）がある。**
  `fa-caret-right` は 65/512em。画面の端にぴったり付けたいときは、
  `left` を 0 にするだけでは足りない
- **ずれた分を `left` の数値で吸収しない。** ずれる量が `font-size` に比例
  するので、文字の大きさを変えるたびに合わせ直しになる。`em` で書くか、
  原因になっている指定そのものを打ち消す

## 文書の語（wording の指摘と、どう決めたか）

`wording` が前例の無い語を 16 挙げた
（[wording-report.md](../agents/TODO-042/wording-report.md) の「2 回目」）。
**直したのは 1 つだけ。**

- **「帳尻を合わせる」を書き直した。** 慣用句としては普通だが、ここで
  言いたいのは「ずれた分だけ `left` をずらす」という具体的な話で、
  つじつま合わせという含みは要らない
- **「字面」は残し、初出に説明を足した。** 前例が 5 件あるが、そちらは
  「文面上・見かけ上」の意味で、今回の「グリフが実際に描かれる範囲」
  とは別物。タイポグラフィでは普通の語なので、言い換えずに
  「字面（グリフが実際に描かれる範囲）」と一度補った
- **「left side bearing」「グリフ」「輝度」はそのまま。** フォント・
  画像処理で一般に通用する専門用語で、訳したり言い換えたりすると
  かえって伝わらない
- **verifier の報告ファイルに出てくる語は直していない**（「静的化」
  「飛び出し量」「非白画素」「字面境界」など）。そのとき何を書いたかの
  記録なので、あとから手を入れない。この方針は TODO-041 と同じ
