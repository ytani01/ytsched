## やったこと

### `.claude/agents/wording.md` を作った（sonnet / effort medium）

コミットに入る `.md` から、このリポジトリに前例の無い語を全部挙げる担当。
TODO-025 で決めたとおり、**既知語リストは持たない**、**文書は直さない**、
**対象は担当の報告ファイルを含む `.md` 全部**。

`sonnet` にしたのは、仕事が「語を拾う → `git grep` で前例を見る →
前例の無い語を全部挙げる」で、一般に通用する語かの最終判断は main が
するため（TODO-025 で決めたこと）。

前例を見るコマンドは `git grep -cF <語> HEAD -- '*.md'`。

- `HEAD` を基準にするのは、まだコミットしていない文書自身を数えて
  しまわないため
- `-F` を付けるのは、語に `.` などが入ったときに正規表現として解釈されて
  誤って一致するのを防ぐため
- 一致なしは「出力なし＋終了ステータス 1」なので、`set -e` の下では
  `|| true` が要る

### `.claude/hooks/check-md-commit.sh` と `.claude/settings.json` を作った

`PreToolUse` の `matcher: "Bash"`。`git commit` に `.md` が入っていれば、
`wording` を立てたかを促す。**判断はしない**（`.md` が入っているかどうか
だけを見る）。

**止めない。** exit 0 で `systemMessage` と `additionalContext` の
2 つだけを返し、`permissionDecision` も `hookSpecificOutput` も返さない。
どんな場合も `exit 0` で終わる（`git` が失敗しても、リポジトリの外で
呼ばれても、`jq` が無くても）。

作るなかで、実測して決めたことが 3 つある。

- **`git diff` には `-z` が要る。** 付けないと `archives/todo/` の日本語
  ファイル名が `\346\226\207...` に化けて、促すメッセージがほぼ読めなく
  なる。`tr '\0' '\n'` で改行区切りに戻している
- **一覧は 20 件で打ち切る。** `systemMessage` は 10,000 字までで、
  文書だけのコミットに `.md` が数十個入ることは普通にある
  （`95895c1` で 12 個）。促すのが目的なので全件は要らない
- **`git commit` の判定は「拾いすぎる側」に倒した。** 止めない hook
  なので、`git log --grep commit` を拾ってメッセージが 1 回余分に出るのと、
  促し損ねるのとでは、後者のほうが困る

### reviewer の指摘 4 件のうち 3 件を直した

- **`settings.json` の `if` を外した。** `"if": "Bash(git commit *)"` と
  書いてあったが、permission rule の前方一致は `Bash(git commit:*)`
  （コロン）の形で、空白＋`*` は文書にある 2 形式のどちらでもない。
  効いた場合に `git add -A && git commit …`（このリポジトリで実際に
  使う形）を弾いて、**hook が黙って発火しなくなる**。スクリプトが自前で
  `git commit` を判定しているので冗長でもあった
- **`wording.md` の `git diff` にも `-z` を付けた。** hook 側で必須と
  判断した直しが定義側に入っておらず、非対称になっていた
- **pathspec 付きの `git commit` を拾えるようにした。**
  `git commit -m "docs(todo): …" TODO.md` は `--cached` にも `-a` にも
  当たらず、`.md` が 0 個と判定されていた。pathspec そのものを正規表現で
  切り出すのは `-m` の引数と見分けが付かず壊れやすいので、**「ステージが
  空なら作業ツリー側も見る」**を手がかりにした。ステージが空で素の
  `git commit` を打つと git 自身がエラーで終わるので、ステージが空の
  `git commit` は `-a` か pathspec のときしかない

**指摘 4（`sudo git commit` / `env FOO=1 git commit` / `timeout 60 git commit`
/ `command git commit` / `/usr/bin/git commit` を拾わない）は見送った。**
このリポジトリでどれも使っていない。塞ぐと正規表現が複雑になり、そのぶん
壊れやすくなる。

`a.py` をステージした状態で `git commit -m x TODO.md` を打つ形も、
今の作りでは拾えない。**承知のうえで見送っている。**

### 定義は 6 個のままにした

TODO-026 では「`runner` を `verifier` に畳めるか見る」としていたが、
**畳めない**。TODO-022 で実測して「決まった手順を流すだけ＝ runner、

`~/.claude/CLAUDE.md` の「3〜4 個に絞る」からはさらに離れるが、担当を

### hook（verifier）

使い捨てのリポジトリを一時ディレクトリに作って確かめた。**本物の
コミットは作っていない。**

| ケース | 結果 |
| --- | --- |
| `.md` をステージ済み＋`git commit -m` | JSON が出る |
| `.py` だけステージ | 出力なし |
| 何もステージなし・`.md` の変更も無し | 出力なし |
| `.md` を未ステージで変更＋`git commit -am` | 拾う |
| 同上で `-a` 無し（ステージに別のものあり） | 出力なし（正しい） |
| ステージ空＋`.md` を未ステージで変更＋`git commit -m x a.md` | 拾う（pathspec） |
| `git status` / `git log --oneline \| grep commit` | 出力なし |
| `git commit --amend --no-edit` | `-a` と誤認しない |
| リポジトリの外 | 出力なし |
| 空の stdin / `not json` / `{}` | 出力なし |
| ファイル名に引用符・空白・日本語 | 正しく出る |
| `.md` 27 個 | 20 個＋「（ほか 7 件）」 |

**全ケースで終了ステータスは 0、stderr は空。** 出た JSON はすべて
`jq -e .` に通した。`shellcheck` の指摘なし。

**実際に Claude Code が hook を発火させるところは、まだ試していない。**
Claude Code は起動時にしか設定を読まないので、`settings.json` を効かせる
には**利用者による再起動**が要る。

### `wording`（効き目の確認）

TODO-025 で使ったのと同じ条件——「足場」が入ったコミット `95895c1` の
`.md` 12 個を、`95895c1^` を基準に見る——で、実際に担当を立てた。

**前例の無い語は 8 語。「足場」が 1 番目に挙がった。**

`足場 / ゴールデンマスターテスト / まとめ役 / 呼び出し口 / 受け側 /
かたまり / 差し戻す / 素通り`

TODO-025 の見込み（正規表現で切ると 15 語、うち「件追記」「全部通」
「直接確」「直接見」の 4 語は切れ端）に対して、**担当に読ませたら 8 語で
切れ端はゼロ**だった。「語を拾うのは担当が読んでやり、`git grep` は前例の
有無を答えるだけにする」という TODO-025 の判断が、そのまま効いている。

見立ても分かれた。「ゴールデンマスターテスト」「かたまり」「差し戻す」
「素通り」は一般に通用する語、「足場」「呼び出し口」「受け側」は
このリポジトリだけの言い換え、「まとめ役」は判断できない、と報告してきた。
**判断できないものを判断できないと書いてくる**のは、決めるのが main
という線引きが守られているということ。
