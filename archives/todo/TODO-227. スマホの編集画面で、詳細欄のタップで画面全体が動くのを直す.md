## きっかけ

Android Chrome の編集画面で、長い詳細を入れた欄の下の方をタップすると、画面全体が動いてカーソルが見えなくなることがあった。編集画面の JS にページを動かす処理は無く、固定の高さの欄をキーボードの上で見せるためにブラウザが動かしていたと見た。原因は実機では切り分けていない。

## やったこと

- `src/ytsched/webroot/static/js/edit-page.js`: 詳細欄にフォーカスがあり、画面が基準の高さより縮んでいる間は、欄を上下のバーの間いっぱいに広げ、上端が上のバーのすぐ下に来るまでページを動かす。フォーカスが外れたら計算の高さへ戻す
- 基準の高さは、入力欄にフォーカスが無いときの `resize` で更新する。幅だけの `resize` では手で変えた高さを戻さない
- `tests/test_browser.py`: 上の動きのテストを 5 件足した
- 最初の案（`c1838f5`、欄を縮めるだけ）は、実機で欄が狭くなりすぎたので `64c379f` で置き換えた

## 確かめたこと

- 利用者が Android Chrome の実機で確かめ、直った
- verifier が実際のアプリと chromium で、viewport の高さを 780px から 430px に変えて 6 項目を測り、すべて期待どおりだった（`archives/agents/TODO-227/verifier-report.md`）
- 足したテスト 5 件は通り、処理を 6 通りに壊すとそれぞれ 1〜2 件落ちる（`implementer-report.md` の第 3 回）

## 担当の指摘の扱い

| 指摘 | 扱い |
|------|------|
| 欄が縮むとカーソルが欄の外に出る | 実機で問題なし。処理は足さない |
| 手で変えた高さが戻る | 幅だけの変更では戻らないよう直した |
| テストが無い、弱い | 5 件に増やして直した |
| 窓を低くしてから欄をクリックするとページが動く | フォーカスが無いときは直した。入力欄にフォーカスしたまま縮めた場合は TODO-228 |
| 横向きで開くと広がらない | フォーカスが無いときは直した。フォーカスしたままの回転は TODO-228 |
| 離れたあとの低い `resize` の順序、広げている間の `resize` でページが戻る、407px 未満の画面 | TODO-228 |
| `behavior: "instant"` のコメントが実態と合わない | `edit-page.js` は直した。`main-page.js` は TODO-229 |

| iOS Safari の動き | 読み合わせのみ。`resize` が起きない見込みで、悪くなる点は見つからなかった。実機の不具合が出たら項目を立てる |
| 編集後の hook で ESLint が動かない | TODO-230 |
