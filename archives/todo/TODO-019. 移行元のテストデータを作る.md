# TODO-019. 移行元のテストデータを作る

見込み: main = Opus 5 / effort high、担当 = main + verifier
実施: main = Opus 5 / effort high、担当 = main + verifier

## きっかけ

JSON Lines への移行ツール（TODO-020）を作るには、変換元のデータが要る。
手元の `~/ytsched/data` は空で、既存データは `tmp_test_data/` にあるが、
これは個人の予定そのものでリポジトリに入れられない。

そこで、**実データの構造だけを写して中身を架空にした合成データ**を
作った。

## やったこと

置き場所は `tests/data/old_format/` にした（利用者と相談して決定）。
`tests/` の中に置けば既存のテストから素直に参照でき、あとで JSON Lines
側のサンプルが要るときは `tests/data/jsonl/` を並べられる。

- **`tests/make_test_data.py`** — 合成データを書き出すスクリプト。
  中身は固定で、何度実行しても 1 バイトも変わらない。
  `README.md` だけは消さずに残す
- **`tests/data/old_format/`** — 11 ファイル（euc_jp 3・utf-8 7・空 1）。
  どのファイルが何を再現しているかは、そのディレクトリの `README.md`
- **`.gitignore`** — `*.bak` に当たって `{日}.cgi.bak` が追跡できないので、
  打ち消しの指定を足した

再現した特徴は TODO-019 に挙げたものを一通り。utf-8 と euc_jp の両方、
どちらでも読めない 1 行を含むファイル、二重エスケープと実体参照、
`★` `(キャンセル` `(欠` `x` で始まる `title` と全角括弧、空の `title`、
空のファイル、`28:00`、時刻欄の 4 通り、長さ 13〜18 文字の `sde_id` と
重複、`ToDo.cgi`、移行の対象外ファイル。

「どちらでも読めないバイト」は `\xad` の 1 バイトにした。実データの
13 ファイルを調べたところ、壊れていたのは実際にこの形（euc_jp の
2 バイト文字の片割れが落ちたもの）だった。

### 仕様書（`docs/data-format.md`）も直した

実データを調べ直して、書いていなかったことが 2 つ見つかった。利用者に
確認したうえで、この項目のなかで直した。

- **`detail` に U+2028（LINE SEPARATOR）が 1 件ある。** `str.splitlines()`
  は U+2028 でも行を切るので、移行ツールがこれを使うと 1 件が 2 行に
  割れて壊れる（前半が `sde_id` 1295 文字の行、後半が 6 列の行になる）。
  行に分けるときは `split("\n")` を使う。合成データにも入れた
- **`{日}-backup.cgi` と `{日}.cgi.bak` も 7 列だった。** 「列の数からして
  違う」が当てはまるのは `iappli_log.cgi` などのほう。この 2 つを対象外に
  する理由は「列が違うから」ではなく「移すと同じ予定が二重になるから」

### 実データには無いが入れたもの

**列の数が 7 でない行**（6 列と 8 列）。実データには 1 行も無かったが、
移行の手順 2 が「7 個に満たなければ空文字で埋める」「8 個目から先は
`detail` の続きとしてつなぎ直す」と決めているので、それを試せるように
した。
