## きっかけ

2026-08-26 に、利用者から「ホームボタンで今日に移動したあと、左の矢印や
左スワイプで前の週に行かない」と言われた。

`my.js` の `moveToMonday()` は `cur_day`（今表示している日付）から前後の
月曜を計算していた。前へ送るときは `1 - wday` で「その週の月曜」を出し、
`cur_day` が月曜のときだけ `-7` に補正していたので、**週の途中の日付から
前へ送ると同じ週の月曜になって動かなかった。** ホームボタンは
`date=今日` を渡すため、今日が月曜以外なら必ずこれに当たる。

サーバー側は渡された日付から月曜を計算して週を出しているので、表示されて
いた週自体は正しい。ずれていたのは、次に要求する日付だけだった。

## やったこと

`moveToMonday()` の `days` の計算を、**まず `cur_day` をその週の月曜まで
戻してから前後へ 7 日ずらす**形にした。変更はこの 1 箇所だけ。

```javascript
const days = (1 - wday) + (direction > 0 ? 7 : -7);
```

（`wday` は日曜を 7 に直したあとの 1〜7）

月曜かどうかの場合分けが要らなくなり、分岐ごと消えた。**次の週へ送る側は
`(1 - wday) + 7 == 8 - wday` で、元の式と同じ**（reviewer が確認）。

ホームボタンが渡す日付を月曜に変える案は採らなかった。検索結果から週の
途中の日付で開いたときに同じことが起きるため。**ホームボタンのあとの
スクロール位置は今までどおり今日のブロックに合わせる**（利用者に確認済み）。

## 滑らせて見せる週とのずれも、ついでに消えた

reviewer の指摘（対応不要の参考として報告されたもの）。サーバーは
`.my-week-prev` / `.my-week-next` を表示中の日付から ±7 日した週で作るので、
**直す前は「前の週へ滑って見せてから、同じ週を開き直す」ことになっていた。**
今回の修正で、滑らせて見せた週と実際に開く週が一致する。

## テスト

`mise run lint` / `mise run test`（439 passed）に加えて、verifier が
playwright で実際に触った（`archives/agents/TODO-063/verifier-report.md`）。

- 水曜（2026-08-26）にホームボタン → ◀ で 2026-08-17（前の週）へ
- そこから ▶ で 2026-08-24 → もう一度 ▶ で 2026-08-31
- 月曜を表示している状態からの前後の週送り
- URL の `date=` と画面側の `#cur_day` が毎回一致すること
  （TODO-049 の、URL だけ変わって画面が変わらない退行が無いこと）
- **変更前のコードに戻すと、同じ手順で 2026-08-24（同じ週の月曜）に
  止まること**。リポジトリは触らず、playwright の `page.route()` で
  `my.js` の本文だけ差し替えて再現させた

**検索結果から週の途中の日付で開いたあとの週送りは、ブラウザでは
確かめていない。** 日付の計算は同じ経路を通るので同じように直るはずだが、
検索モードでは隣の週が DOM に無く（`hasAdjacentWeek()`、TODO-057）、
滑らせずに移る経路になる。

## 残っているもの

**元のコードから引き継いでいる計算方法で、今回の変更が持ち込んだものでは
ない。** 項目は立てていない。
