## きっかけ

TODO-049 で 1 画面 1 週間の表示にしたあと、画面に残っていた 2 つの
ちぐはぐを直す。TODO-049 から分けて立てた（2026-08-26）。

- **どの週を見ているのかが画面から読み取れない。** 各日に今日からの
  日数差（`+3` `-12`）は出ていたが、週として何週離れているかは、
  左端のゲージの針の位置から読むしかなかった
- **日付の欄（左端の列）を押しても何も起きない。** 押すとその日を先頭に
  した一覧へ移る作りだったが、週表示ではその日がすでに画面に出ている
  ので、同じ週の中では画面が変わらない

## やったこと

### 上部に週バーを新設した

`position: fixed` で画面の上端に固定し、左に表示している週の範囲
（`2026/08/24 – 08/30`）、右に今週から何週離れているか（`+3w`）を出す。

- **今週のときは、週の差を出さない**（何も出ないこと自体が「離れて
  いない」しるしになる）。書き方はゲージのラベル（`+1w` `-3d`）に
  合わせた
- **検索モードでは週バーそのものを出さない。** 検索結果は日付が飛び飛び
  で週の区切りに合わず、期間は検索側のバーがすでに出している

週の差は Python 側で数える（`main_handler.py` の `calc_week_diff()`）。
**どちらも月曜へ丸めてから引く**ので、差は必ず 7 の倍数になり、
日曜と翌月曜のように 1 日しか離れていなくても `+1` になる。

```python
monday = date - datetime.timedelta(date.weekday())
this_monday = today - datetime.timedelta(today.weekday())
return (monday - this_monday).days // 7
```

範囲の表示には、テンプレートへすでに渡っている `date_from` / `date_to`
をそのまま使った。通常モードではこの 2 つが週の月曜と日曜になっている
（TODO-049）。

週バーは `position: fixed` なので、そのままだと一番上の日付ブロックが
下に隠れる。**メニューバーで `padding-bottom` を入れているのと同じ
やり方**で、`onloadHdr()` が週バーの高さぶんを `body` の `padding-top` に
入れる。**`body_h` を測るより先に入れること**（あとに置くと、1 画面に
収まるかどうかの判定が週バーの高さぶん狂う）。検索モードでは要素が
無いので、`if (elWeekBar)` で弾いて 0 のままにする。

CSS の `.fixed-top` は、既存の `.fixed-bottom` に合わせて Bootstrap から
写した（`z-index` も同じ 1030）。

**「週バー」という呼び方は、ここで決めた。** 立てたときは「ヘッダ」と
呼んでいたが、`main.html` の `<header>` は中身が `<script>` だけで別物
なので紛らわしい。画面の下にある「メニューバー」と、要素の id
（`week_bar`）に合わせた（wording の指摘から決めた）。

### 日付の欄を押したら、その日に予定を追加するようにした

`onmousedown` を、通常モードでは新規追加の画面（`edit/`）へ移るように
差し替えた。各日の下にある小さな `+` ボタンより押しやすい。

**検索モードのときは今までどおり**、その日を含む週へ移って検索を解除
する（`search_str` を空で POST）。検索結果から「この日の週を見たい」は
残っている操作なので、そちらを潰さない。

出し分けはテンプレートの `{% set %}` で属性の中身を組み立てている。
属性値は autoescape で `&#x27;` になるが、HTML の解析でクォートへ戻って
から JavaScript に渡るので、これまでの `{{ obj }}` と同じ扱い。

### 各日の日数差とホームボタンは、変えていない

立てたときは「週の差をヘッダに出す代わりに、各日の日数差をやめる」
「今週から離れているときだけホームボタンを目立たせる」も入っていたが、
**どちらも見送った**（着手時に利用者と決めた）。

- **各日の日数差はそのまま残す。** 週の差と日数差は別の情報で、
  どちらも要る
- **ホームボタンは目立たせない。** 週バーが出れば離れているのは
  分かるので、それ以上の合図は要らない

## 見送った指摘

reviewer から、確信度の低い指摘として「ゲージの `centerY` が、新設した
週バーの高さを踏まえていないのではないか」が出た。**直さないことにした。**

週バーは `position: fixed` なので `document.documentElement.clientHeight` を
変えない。つまりゲージの計算は変更前とまったく同じで、変更前後の
キャプチャでもラベルの位置は動いていない。極端な目盛り（`-30y` 側）が
画面の外や週バーの下に入るのは、下端がメニューバーに隠れるのと同じ
で、以前からの作り。
