# TODO-015 の分担

ruff の整形・書き換え系の指摘（84 件）を解消する。

- `implementer` — ruff の指摘の解消と `pyproject.toml` への除外設定
  （[報告](implementer-report.md)）
- `verifier` — diff の読み合わせ、lint・型チェック・テスト、アプリの
  起動確認（[報告](verifier-report.md)）

## この分担にした理由

84 件が 10 ファイルにまたがるうえ、printf 書式から f-string への
書き換えは**引数の順序や桁の指定を取り違えても、テストが通ってしまう
種類の間違い**が起きやすい。数が多いぶん一つひとつは単純なので、
実装を `implementer` に任せ、確認は別に `verifier` へ分けて
「動作が変わっていないか」を diff から読ませた。

`reviewer` は付けていない。設計の判断が要らず、規則ごとの対応方針は
main が先に決めているため（下記）。

## main が先に決めた方針

- `DTZ011` / `DTZ005` は**規則ごと除外**する。除外は
  `pyproject.toml` の `[tool.ruff.lint]` に書く（コマンドラインに
  書くと、素の `ruff check` やエディタの LSP では出たままになる）
- `EXE001` はシェバンを消す（単体実行しないモジュール。相対 import が
  あり直接実行しても動かない）
- `D419` は「空だから消す」ではなく、**中身を書ける箇所は日本語で書く**
- `FLY002` は、テストの意図が読みにくくなるなら書き換えずに残してよい
  （判断は implementer に委ねた）
