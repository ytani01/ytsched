# TODO-077 reviewer 報告

## 確信度の高い指摘

### 1. `_dirty_dates` が例外で残ると、次の（無関係な）リクエストで
   意図しないファイルが保存される

`self._sd`（`SchedData`）は `webapp.py` の `tornado.web.Application` の
設定（`sd=self._sd`）経由でアプリ全体に 1 つだけ生成され、リクエストを
またいで使い回される（handler ごとに作り直されない）。

一方 `exec_update()` は次の順で動く。

```
cmd_del(orig_date, sde_id)   # _dirty_dates に orig_date を足す
cmd_add(...)                 # _dirty_dates に date を足す
self._sd.save()              # 溜まった _dirty_dates をまとめて保存し、空にする
```

`cmd_del()` が成功したあと `cmd_add()` の途中で（想定外の）例外が起きて
`exec_update()` を抜けると、`self._sd.save()` に到達しないまま
`_dirty_dates` に `orig_date` が残る。この `SchedData` は次のリクエストでも
使い回されるので、**次に来た別のリクエスト**（別の日付を編集するだけの
`fix`/`add` など）が最後に呼ぶ無条件の `self._sd.save()` が、この残った
日付も一緒に拾って保存してしまう。

- 依頼書の気をつけること「例外で途中で抜けたときに保存されないのは
  今までと同じで悪化ではない」は、**その場のリクエストで保存されない**
  ことだけを見ており、**残った印が次のリクエストの保存に紛れ込む**
  ことには触れていない。これはこの変更で新しく開いた経路
  （以前は `add_sde()`/`del_sde()` が呼ばれるたびに即 `save()` していたので、
  「次のリクエストに持ち越す」余地自体が無かった）
- 実際に踏みやすいかは、`cmd_del()` 成功後 `cmd_add()` が例外を出す
  条件次第（現状の `SchedDataEnt` の直接コンストラクタは素直な入力では
  例外を出しにくく、頻度は低いと見る）。ただし依頼書の 3 番の疑問
  そのものであり、「今までと同じで悪化ではない」という判断の前提が
  ずれている点は指摘に値する

## 確信度が中程度の指摘（依頼書 1 番について）

### 2. `SchedData.save()` が `get_sdf(date)` で引き直す設計は、
   LRU で捨てられると変更が消える経路を理論上持つ

`get_sdf()` はキャッシュが `_cache_size` 以上になると、古い方から
`CACHE_DISCARD_RATE`（10%）を `popitem(last=False)` で捨てる
（`ytsched.py:773-780`）。`add_sde()`/`del_sde()` は変更した
`SchedDataFile` オブジェクトそのものではなく「日付」だけを
`_dirty_dates` に残すため、`save()` の時点でその日付がキャッシュから
すでに追い出されていると、`get_sdf(date)` は**ディスクから読み直した
別インスタンス**を返す。その新しいインスタンスには、追い出される前に
メモリ上で行った変更（`add_sde`/`del_sde` の結果）が乗っていないので、
変更はディスクへ一度も書かれずに消える。

- 既定の `DEF_CACHE_SIZE = 20000` に対し、1 回のリクエストで
  `_dirty_dates` に積むのは `fix` でも高々 2 件（`orig_date` と `date`）
  なので、**現状の呼び出し方では実際には踏めない**（20000 件近くの
  異なる日付を 1 リクエストで触らないと discard が起きない）
- ただし `SchedDataFile` そのものではなく日付を覚える設計は、
  将来 `cache_size` を小さくする（テストでは `cache_size=10` の例が
  既にある）、または一括操作で多数の日付を 1 リクエストで触るように
  なると、黙って変更が消える経路になる。依頼書で名指しされていた点
  そのものなので、設計として「`SchedDataFile` を直接覚える」方が
  頑丈だとは思うが、**現状の呼び出し方では実害が無い**ため、
  直すかどうかは main の判断に委ねる
