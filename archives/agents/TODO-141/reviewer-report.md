## 高い確信の指摘

### 1. JSON としては読める壊れた行も、選択した組と一致すると消える

- 該当: `src/ytsched/trash.py:157-168`
- 問題: `delete_many()` は JSON のオブジェクトで `sde_id` と
  `trashed_at` が文字列なら、`SchedDataEnt.from_dict()` では読めない行でも
  削除する。`entries()` が警告して飛ばす壊れた行も保持するという
  docstring（同:137-138）と、壊れた行を残すデータ形式の決まりに反する。
- 再現条件: 表示できる項目と同じ `(sde_id, trashed_at)` を持つ一方で、
  `date` が無い・日付でないなど `SchedDataEnt.from_dict()` が失敗する
  JSON オブジェクトが `trash.jsonl` に混在している状態で、その項目を
  削除する。この壊れた行も一緒に書き落とされ、復旧の手がかりを失う。
- 対応案: 削除対象と判定する前に `SchedDataEnt.from_dict()` まで成功する
  行だけを対象にし、それ以外の行は生のまま保持するテストを加える。

## 確認結果

- 上記以外に、選択組のペアリング、空・不一致・不正日時・一致なしの
  リクエスト、表示外項目の保持、復活操作、画面の選択・確認・遷移について、
  確信度の高い問題は見つからなかった。
- 指示に従い、テストは実行していない。

## 再レビュー

- 指摘 1 は解消した。`delete_many()` は `trashed_at` の型確認と

  無いなど `entries()` が飛ばす行は保持される。
