# TODO-064 の分担

## どう分けたか

| 担当 | 依頼書 | 報告 |
|------|--------|------|
| verifier | `verifier-request.md` | `verifier-report.md`・`verifier-report2.md` |
| reviewer | `reviewer-request.md` | `reviewer-report.md` |
| wording | — | `wording-report.md`・`wording-report2.md` |

実装は main が行った。見込みの `main のみ + verifier + reviewer` のとおり。

## その分担にした理由

- **implementer を分けなかった。** 触るのが `my.js` と `main.html` の
  2 ファイルで、`my.js` の中でもスワイプの部分だけに閉じていたため
- **reviewer を入れた。** `stopPropagation()` で伝播を止めるという、
  一覧画面のクリック全部に関わるやり方を採ったため（TODO-017 の
  「挙動や分岐が変わる項目には入れる」）。実際、**指摘 2 件はどちらも
  「黙って何も起きない」経路**で、テストが通ることを見ても出てこない
  種類のものだった
- **verifier を分けた。** クリックが今までどおり効くかは、実際に
  ブラウザで触るしかない。ここが壊れると一覧から何も開けなくなる

## 気づいたこと

- **reviewer と verifier を同時に走らせたが、reviewer が先に終わった。**
  verifier がブラウザで触っている最中にコードを直すと、どちらの版を
  確かめたのか分からなくなるので、verifier の報告を待ってから直した。
  そのぶん待ちが増えるので、**確認に時間のかかる担当が先**に終わる
  ようにしたほうがよかった
- **verifier への依頼書に「ここが壊れると一覧から何も開けなくなる」と
  書いた**のが効いた。クリックの確認を最優先で組み立ててくれた。
  TODO-061 の「心配なところを名指しで書く」と同じ
- **reviewer の指摘 1 は、こちらが確かめ方に書いていなかった範囲だった。**
  「5px 以内ならクリック」という値を自分で決めておきながら、5〜60px の
  間に何も起きない範囲ができることに気づいていなかった。TODO の
  「確かめ方」にも書いていないので、verifier だけでは出てこなかった
