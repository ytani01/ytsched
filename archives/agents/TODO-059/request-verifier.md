# TODO-059 verifier への依頼（2 回目・最終形）

**1 回目（`verifier-report.md`）のあとに、目盛りの構成と定数が変わった。**
そちらの報告は式の確認としては生きているが、いまの状態とは違う。

## 何をした変更か

ヘッダの横ゲージ（TODO-058）で、`-1w` と `+1w` の間だけが 21.8% 空いて
広く見えるのを詰めた。目盛りの位置を決める式を変えてある。

```
今まで: log10(日数 + 0.6)    / log10(30年 + 0.6)
これから: log10(1 + 日数 / 10) / log10(1 + 30年 / 10)
```

日数を割る `DAYS_GAGE_K` は 10。`-1w` と `+1w` の間隔は 7.6% になる。

**目盛りも 8 個から 14 個に増やした。** 片側 `1w`・`1m`・`3m`・`1y`・
`3y`・`10y`・`30y` の 7 つ。1 → 3 → 10 の並びは対数の上で等間隔になる
ので、目盛りの間隔が 6.2〜9.4% に揃う。

触ったファイルは 2 つ。

- `src/ytsched/main_handler.py` の `days2x_percent()`、新しい定数
  `DAYS_GAGE_K`、目盛りの一覧 `GAGE`
- `src/ytsched/webroot/static/js/my.js` の `days2xPercent()` と、
  新しい定数 `DAYS_GAGE_K`

`days == 0` を特別扱いして 0 を返していたのは、新しい式ならそのまま 0 に
なるので消した。

1. **Python と JavaScript が同じ値を返すこと。** 日数をいくつか
   （0、1、7、30.4375、365.25、10957.5、それを超える値、負の値）
   入れて、両方の実装で突き合わせる。JavaScript は `node` で動く
2. **Python と JavaScript の `DAYS_GAGE_K` が同じ値であること**
3. `mise run fmt` / `typecheck` / `lint` / `test` が通ること
4. **14 個のラベルが、どれも重なっていないこと。** アプリを起動して
   キャプチャを撮る。幅は 360px・412px・800px の 3 つ。
   **360px でいちばん狭いのは `+1w` と `+1m` の間で、余白は 1.1px の
   見込み。** ここが 0 を割っていないかを見る
5. **針が週ごとに動いて見えること。** 今週・+1w・+1y の週を出して、
   針の位置が変わることを見る。URL は
   `http://localhost:10085/ytsched/?date=2026-09-02` の形
   （**日付は ISO 形式。`2026/09/02` はスラッシュのせいで読めず、
   黙って今週が出る**）
6. 端（±30y）とそれを超えた日数で 50% に止まること

## 気をつけること

- **アプリを起動するときは `--datadir` に一時ディレクトリを指定する**
  （`~/ytsched/data` の実データを汚さない）
- **ポート 10085 には、利用者が別のアプリを動かしていることがある。**
  `pgrep -af "ytsched webapp"` で見てから使う。別のポートでもよい。
  **`kill $(pgrep -f ...)` は自分のシェルを巻き込む。**
  PID を確かめてから、その PID を kill すること
- キャプチャは `env -u DISPLAY mise run shot -- <URL> --width 360
  --width 412 --width 800 -p <名前>` で撮れる。
  保存先は `~/tmp/playwright-mcp/`
