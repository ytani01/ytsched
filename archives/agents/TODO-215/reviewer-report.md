## 指摘

### 1. 検討 — 日付の欄が画面より高い日は、日付と先頭の予定が週バーの裏へ隠れる（この差分で起きる退行）

`main-page.js` L469-472。

`block: "nearest"` は、要素が画面より大きいと上端を画面の上端（y=0）に合わせる。日付の欄（`.my-date-col`）はその日の予定の行の高さまで伸びるので、予定の多い日は画面より高くなる。固定の週バー（`#week_bar`、0〜68px）は考慮されない。

実測（1 日に 40 件、`sde_align=top`、週間表示）:

| | scrollY | 日付の欄 top | 先頭の予定 |
|---|---|---|---|
| flash なし | 632 | 100 | 101〜125（見える） |
| flash あり | 732 | 0 | 1〜25（週バーの裏） |

`onloadHdr()` の `scrollToDate()` が合わせた位置を 100px ずらし、日付と点滅させたい予定の行を隠してしまう。起きるのは日付の欄の高さが画面の高さを超えるときだけ（700px の画面で 1 日おおむね 27 件以上。詳細を複数行持つ予定が多ければもっと少なくて済む）。実際の利用で起きるかどうかは未確認。

### 2. 検討 — 「最初の 1 つ」は常に日付の欄で、点滅させたい予定の行は見える位置へ来ない

`block: "nearest"` が見るのは画面の端で、固定の週バー（上 68px）、フッターのゲージ（590〜658）、メニューバー（658〜700）は考慮されない。700px の画面のうち 178px がこれらに覆われる。どの要素を見せるか（予定の行を優先するか）、固定バーをどう扱うかは main の判断。

## 前回の指摘の結果

- 指摘 1（日付の欄が画面より高い日の退行）: **解消した。** 40 件の日、`sde_align=top`、先頭の予定を flash: `scrollY` 524 のまま、先頭の予定は 101〜121（flash なしと同じ）。日付だけの flash でも、日付の欄の上端は 100 から 98 に動くだけで、週バーの裏には入らない
- 指摘 2（予定の行が見える位置へ来ない）: **解消した。** 週間表示の flash ありでは、どの組み合わせでも、予定の行が 98〜560（帯の間から上下 30px を除いた範囲）に収まった。例:
  - 40 件の日、top、末尾の予定: 940〜959 → 540〜559
  - 12 件の日、bottom、末尾の予定: 674〜693（メニューバーの裏） → 540〜559
  - 40 件の日、bottom、先頭の予定: -165〜-145（画面の上の外） → 99〜119（上が隠れる分岐）
  - home、先頭の予定: 35〜55（週バーの裏） → 99〜119
  - 検索モード、末尾の予定: 654〜678（メニューバーの裏） → 631〜655。文書の末尾で `scrollY` が上限（maxY）に当たるので余白 30px は取れないが、メニューバー（658）より上には出る
- 指摘 3（テストが無い）: テストは足された。ただし下の「検討 1」

## 分岐の読み

- 収まっている（上下とも余白の内側）: `dy = min(0, 正)` = 0。動かない（flash なしと `scrollY` が一致したケースで確認）
- 上端が週バーの下端から 30px 以内（隠れてはいない）: `min` で負になるが、`r.top >= top` の判定で 0 に戻る。正しい
- 下が隠れる: 下端を下の帯の 30px 上へ。`min` が、上端が上の帯を越えない範囲に抑える。正しい
- 上が隠れる、両方隠れる: 負の `dy` で上端を週バーの 30px 下へ。上端を優先する。正しい
- 検索モード: `#week_bar` も `#footer_gauge_bar` も描かれない（`main.html` の `{% if not search_mode %}`）。`?? 0` と `|| menu_bar` で、上は 0、下はメニューバーになる。検索の帯（`.my-search-bar`）は固定配置ではないので、上が 0 で合っている。`#menu_bar` は条件なしで描かれるので null にはならない

## 指摘

### 検討 1 — テストが押さえているのは「下が隠れる」分岐だけ

`tests/test_browser.py` の `test_flash_scrolls_sde_between_bars`。

この依頼の `?date=…&sde_align=top` では、予定の行は下にはみ出すだけになる。そのため、次の行を消してもテストは通ると読める（コードを書き換えられないので、消して走らせてはいない。未実測）。

- `dy = Math.min(dy, r.top - top - margin);`（上が隠れる分岐と、前回の退行を防ぐ部分）
- `if (r.top >= top && dy < 0) { dy = 0; }`

上が隠れる場合は、実際に起こり得る。検索モードの編集は `sde_align=bottom` で送られ、その日のヒットが画面より多いと、先頭の予定が画面の上の外に出る（週間表示の bottom で -165 を実測）。`sde_align=bottom` で、予定の多い日の先頭の予定を flash するケースを 1 本足すと、この分岐を押さえられる。

### 好みの範囲 — 画面より高い要素は 2px ずれる

日付だけの flash（del）で日付の欄が画面より高いと、`dy = min(正, 100 - 68 - 30) = 2` で 2px 下へずれる（`scrollY` 524 → 526）。`scrollToId()` の余白 30 がメニューバー基準の位置と 2px 違うためで、見た目への害は無い。
