# TODO-019 の分担

## 誰に何を担当させたか

| 担当 | 何をしたか | 報告 |
| --- | --- | --- |
| main | 実データの調査、合成データの設計、`tests/make_test_data.py` の作成、`README.md`・`docs/data-format.md` の執筆 | — |
| verifier | 挙げた特徴が全部再現できているかの確認 | [verifier-report.md](verifier-report.md)（依頼は [verifier-request.md](verifier-request.md)） |

## なぜこの分担にしたか

項目を立てたときの見込みどおり `担当 = main + verifier`。

**implementer は立てていない。** 作るのはテストデータと、それを書き出す
だけのスクリプト 1 本で、アプリのコードには一切触らない。込み入った
ロジックも無い。

**verifier は立てた。** 「仕様書に挙げた特徴を全部再現できているか」は
実際に数えれば確かめられる。作った本人は「そのつもりで書いたのだから
入っているだろう」で通してしまうところで、TODO-017 で決めた
「書式の確認だけなら main、試せる手順があるなら分ける」に当てはまる。

**reviewer は入れていない。** アプリの挙動も分岐も変えていない。

## 途中で分かったこと

実データを調べ直したところ、`docs/data-format.md` に書いていなかった
ことが 2 つ見つかった。利用者に確認したうえで、この項目のなかで仕様書も
直した。

- **`detail` に U+2028（LINE SEPARATOR）が 1 件ある。** `str.splitlines()`
  は U+2028 でも行を切るので、移行ツールがこれを使うと 1 件が 2 行に
  割れて壊れる。合成データにも入れた
- **`{日}-backup.cgi` と `{日}.cgi.bak` も 7 列だった。** 仕様書の
  「列の数からして違う」が当てはまるのは `iappli_log.cgi` などのほうで、
  この 2 つは中身が同じ形の過去の版。対象外にする理由は「列が違うから」
  ではなく「移すと二重になるから」なので、そう書き直した

## verifier の定義について

`.claude/agents/verifier.md` に「データ形式（タブ区切りテキスト）は
変えない」と書いてあるが、これは TODO-018 で覆っている。今回は依頼に
「既知」として明記して回避した。定義そのものの書き直しは、TODO-020 に
着手するときに判断する。
