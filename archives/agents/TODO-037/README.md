## 分担をこうした理由

- **implementer を分けた。** 触るのは `base.html` の 6 行と `README.md`
  だけだが、外部から 8 ファイルを取ってきて置き場所を決め、ハッシュで
  照合し、ライセンスを揃える手順がまとまってあった。「実装とテストと
  文書がまとまって要る」の目安に当たる
- **verifier を分けた。** `~/.claude/CLAUDE.md` のとおり、コードを変える
  項目では確認を必ず別の担当にする。今回は試せる手順（起動して curl、
  `.woff2` の先頭を見る、wheel の中身を見る）がまとまってあったので、
  書式の確認だけで済む類いではなかった
- **reviewer は立てなかった。** 分岐も挙動も変えていない（読み込み元が
  変わるだけ）。`CLAUDE.md` の「挙動や分岐が変わる項目には入れる」に
  当たらないと判断した
- **wording は 2 回立てた。** 立てるコミット（`TODO.md`）と、決着の
  コミット（archives・`README.md`・担当の報告ファイル）でそれぞれ
- **見た目の比較は main がやった。** chromium を CDP で動かして画素単位で
  比べる手順は、担当へ渡すより自分で回したほうが早かった。同じ手順を
  TODO-038 でも使う

  重かったのは実装ではなく確認のほう。** 実装は依頼書どおりに進んで
  やり直しが無かった。時間を使ったのは、同梱の前後で画面が変わって
  いないことを確かめる仕組み（CDP でスクリーンショットを撮って画素で
  比べる）を組むところ。**その仕組みは TODO-038 で使い回せる**ので、
  次は見込みどおりに収まるはず

  撮り直すには `git stash` が要る。TODO-038 でも同じ順でやる
- **一覧だけ 0.486% の差が出た。** 目では区別できない文字の縁の差で、
  同じ版を 2 回撮ると 0 画素なのでブレではない。原因は詰めていない。
