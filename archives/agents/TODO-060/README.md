## なぜこの分担にしたか

**実装は main が持った。** 直したのは `my.js` の 2 行で、範囲が小さい。
むしろ手間が掛かったのは原因を突き止めるところで、そちらはブラウザで
`style.left` と `getComputedStyle().left` を突き合わせて調べた
（`probe.py`）。

**確認は verifier に分けた。** コードを変える項目では規模によらず
分けると決めてある（`~/.claude/CLAUDE.md`）。今回のように
「直したつもりで実は効いていない」種類の不具合は、**直した本人が
`probe.py` を走らせても、直ったことにして済ませてしまいやすい**。

- [依頼](request-verifier.md) → [verifier-report.md](verifier-report.md)
- 測り方の道具: [probe.py](probe.py)

## wording

`.md` が入るコミットなので立てた（TODO-025・TODO-026）。
報告は [wording-report.md](wording-report.md)。

`wording` は 3 語（演出・滑らか・「見たいものが見えたことにして
しまいやすい」）を挙げ、「レイアウトを確定させる」も判断を仰いできた。
main の判断はこう。

- 「演出」→ **言い換えた。**「TODO-049 で入れた動き」。TODO-049 側も
  「動かして見せる」と書いてあり、そちらに揃う
- 「見たいものが見えたことにしてしまいやすい」→ **言い換えた。**
  「直ったことにして済ませてしまいやすい」
- 「滑らか」→ **そのまま。** 普通の日本語で、造語ではない
- 「レイアウトを確定させる」→ **そのまま。** `my.js` の
  `// 強制的にレイアウトを確定させる` は TODO-049 のときから
  コードにあり、この項目はその行を直している。**コードのコメントと
  違う語を文書で使うほうが分かりにくい**
