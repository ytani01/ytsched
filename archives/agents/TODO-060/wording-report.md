# TODO-060 wording 報告

対象は依頼書に挙げられた 5 ファイル
（`TODO.md`、`archives/todo/TODO-060. ….md`、
`archives/agents/TODO-060/README.md` `request-verifier.md`
`verifier-report.md`）。基準は `HEAD`（この一連の変更が入る前の
最後のコミット）。

## 前例の無い語

### 演出

- 出てくる箇所: `archives/todo/TODO-060. ….md`「TODO-049 で入れた
  『前に見ていた週の位置から、今の週へ動かして見せる』演出が、実際には
  効いていなかったことになる」
- `git grep` の件数: 前例なし（`.md` 全体で 0 件）
- 見立て: 依頼書は「TODO-049 に前例があるはず」としていたが、
  `git grep -cF 演出 HEAD -- '*.md'` は 0 件だった。TODO-049 側は
  「動かして見せる」という言い回しで書かれており、「演出」という語自体は
  使われていない模様。一般語ではあるが、この文書が初出になる

### 滑らか

- 出てくる箇所: `verifier-report.md`「`54ms〜202ms` にかけて
  `288.344px → 288.688px` へ滑らかに遷移」
- `git grep` の件数: 前例なし
- 見立て: 一般的な語で、造語には見えない。単に初出なだけと判断できる

### 見たいものが見えたことにしてしまいやすい

- 出てくる箇所: `archives/agents/TODO-060/README.md`「直したつもりで
  実は効いていない種類の不具合は、直した本人が `probe.py` を走らせても、
  見たいものが見えたことにしてしまいやすい」
- `git grep` の件数: 前例なし（語というより言い回しなので、地の文の
  一致は無い）
- 見立て: 1 語に切り出せる語ではなく比喩的な言い回し。判断できないが、
  他の項目の README でも似た趣旨（実装者が自分の変更を過信する話）は
  出てくるので、リポジトリ内で定着した呼び名というより、その場の説明に
  見える

## 依頼書が挙げていたが、前例が見つかった語

- **補間**: `TODO-049` の README・依頼書、`TODO-058` の依頼書・
  reviewer 報告などに前例あり（複数件）
- **退行**: `TODO.md`、`TODO-016`・`TODO-049`・`TODO-055` の archives に
  前例あり
- **経路**: 非常に多くのファイルに前例あり（一般語として定着している）
- **突き合わせる**: `TODO-030`・`TODO-038`・`TODO-047`・`TODO-048`・
  `TODO-057`・`TODO-059` の archives に前例あり

## 判断が要る点: レイアウトを確定させる

- 出てくる箇所: `archives/todo/TODO-060. ….md` の見出し「原因 1:
  レイアウトを確定させる 1 行が効いていない」など
- `git grep -cF` の結果: **`HEAD:TODO.md:3`**（3 件）
- 見立て: 機械的には前例ありだが、この 3 件は**すべて `TODO.md` 内の
  旧 TODO-060 節そのもの**（今回のコミットで `archives/todo/` へ
  切り出される直前の記述）。つまり「前のコミットで既に使われていた」
  というより、**この一連の作業の中で最初に使われた語が、今回さらに
  同じ表現で `archives/todo/TODO-060. ….md` へも書き写された**、
  という状態に見える。依頼書がこの語を怪しいと挙げていた理由と
  合わせて、**造語かどうかは main の判断を仰ぎたい**
  （`wording` の基準では前例ありなので候補からは外している）
