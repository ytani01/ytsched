# TODO-040 の分担

Bootstrap 4.5.0 → 5.3.8、Font Awesome Free 5.6.1 → 7.3.1。

| 担当 | 何を任せたか | 依頼書 / 報告 |
|---|---|---|
| main | 上げる先の調査、表示がどう変わるかの実測、利用者との相談 | — |
| implementer | 決まったとおりにファイルを差し替え、クラス名を置換する | [依頼](implementer-request.md) / [報告](implementer-report.md) |
| verifier | 上げても表示が変わっていないことを画素単位で確かめる | [依頼](verifier-request.md) / [報告](verifier-report.md) |
| wording | コミットに入る `.md` から前例の無い語を挙げる | [依頼](wording-request.md) / [報告](wording-report.md) |

## この分担にした理由

### main が先に全部調べた

「最新版に上げる」という一行の項目だが、**上げると表示が変わるのかどうかが
分からないと、担当に渡す依頼書が書けない**。TODO-040 には「どうしても挙動や
表示が変化する場合は、相談して決める」とあり、相談するには何がどう変わるかを
先に測る必要があった。

そこで main が、一時ディレクトリに現状と新版の `webroot` を並べて立ち上げ、
画素単位で比べた。分かったのは 2 つ。

- Bootstrap の差（画素の 26%）は**崩れではなくズレ**で、原因は `body` の
  `font-family` が `system-ui, …` に変わったこと 1 つだけだった。
  `my.css` で 4.5 と同じ値に固定すると 1.0% まで落ちる
- Font Awesome の差は**絵柄そのもの**で、固定では消せない

この切り分けができたので、利用者への相談が「上げるか上げないか」ではなく
「フォントを固定して上げるか」という形にできた。

### implementer を分けた

判断は main が済ませていて、残るのは手を動かす作業。それでも分けたのは、
**vendor 5 ファイル・テンプレート 4 つ・`my.css`・`README.md` にまたがる**
ため。`~/.claude/CLAUDE.md` の「複数のファイルにまたがる」という目安に合う。

依頼書には sha384 の値まで書いた。main が jsDelivr の公開版と突き合わせて
同一を確かめた値なので、implementer はそれと照合するだけで、取得したものが
途中で変わっていないことを確かめられる。

### reviewer は入れなかった

`~/.claude/CLAUDE.md` の基準では「挙動や分岐が変わる項目には入れる」。
今回の変更はクラス名の置換（`text-left` → `text-start` など 10 か所）と
ファイルの差し替えだけで、分岐は 1 つも増えず、Python も JavaScript も
触っていない。崩れは verifier の画素比較で捕まる。

### verifier には手順を渡した

一覧の画面は JavaScript が今日の位置までスクロールするため、
`chromium --headless --screenshot` でそのまま撮ると**真っ白になることが
ある**（main が実測した）。TODO-038 の verifier が使った「静的な HTML を
作ってから撮る」やり方を依頼書に書き写し、加えて main が測った参考値
（フォント固定あり / なしの両方）を渡した。**桁が大きく外れたら何かおかしい**
と分かるようにするため。
