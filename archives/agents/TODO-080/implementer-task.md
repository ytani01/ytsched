# TODO-080 implementer への依頼

`TODO.md` の TODO-080 と `docs/design-review.md` の C を先に読むこと。

## やること

### 1. `mtime` を見て読み直す

`src/ytsched/ytsched.py`。

- `SchedDataFile` に、`load()` したときのファイルの更新時刻を持たせる。
  ファイルが無いときの扱いも決めること（`None` など。**無かったファイルが
  できたときも読み直せる**ようにする）
- `SchedData.get_sdf()` で、キャッシュに当たったら今のファイルの
  更新時刻と見比べ、食い違えば読み直す。`os.stat()` は 1 回で済ませ、
  例外（消えていた、権限が無い）で 500 にしないこと
- `mtime` の分解能に注意。同じ秒の中で 2 回書くと変わらないことがある。
  `st_mtime`（float）と、あわせて `st_size` も見るなど、**取りこぼしを
  減らす方法を選んで、選んだ理由を docstring に書く**

**書き込みの直後に自分で読み直さないこと。** `save()` した直後は
キャッシュの中身がファイルと同じはずで、そこで読み直すのは無駄。
`save()` のあとに更新時刻を持ち直す形にすればよい（TODO-077 で
`SchedData.save()` ができている）。

### 2. `DEF_CACHE_SIZE` を見直す

いまは 20,000。TODO-069 で 1 リクエストが 63 日ぶん（前後 1 ヶ月）を
読むようになったので、実際にはまず捨てられない。

- 何日ぶんが妥当かを、`LoadMonths` の既定（1）と上限（24）から
  見積もる。**上限いっぱい（24 ヶ月 = 前後 2 年）でも捨てられない
  数**を選び、なぜその数かをコメントに書く
- `CACHE_DISCARD_RATE`（0.1）はそのままでよい
- 数を変えたら `tests/` の中の依存を grep で探して直す

## 気をつけること

- **挙動の変更はここまで。** キャッシュを丸ごと捨てる API を足したり、
  タイマーで無効化したりはしない
- ログを出しすぎないこと。読み直しは `debug` で 1 行

## テスト

`tests/test_ytsched.py` の `SchedData` のテストの並びに足す。

- キャッシュに載ったあとでファイルを**外から書き換える**と、
  次の `get_sdf()` で新しい内容が返ること
- 書き換えていなければ読み直さないこと（`SchedDataFile` の
  インスタンスが同じまま、または `load()` が呼ばれないことを見る）
- キャッシュに載ったあとでファイルが**消えた**ときに落ちないこと
- 無かった日のファイルが**あとからできた**ときに読めること
- `SchedData.save()`（TODO-077）の直後に、無駄な読み直しが起きないこと

`mtime` の分解能で不安定になるテストにしないこと（`os.utime()` で
明示的に時刻を動かす、など）。

`mise run fmt` / `typecheck` / `lint` / `test` は叩いてよい。
**`mise run upgradeproject` は走らせないこと。**
アプリの起動を確かめるときは `--datadir` に一時ディレクトリを指定する。
