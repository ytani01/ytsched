## やること

ヘッダの横ゲージ（`.my-gage-bar`）をタップ・クリックしたら、その位置が指す
週へジャンプする。ドラッグでの追従は要らない。

1. `src/ytsched/webroot/static/js/my.js` に、`days2xPercent()` の逆算
   （`xPercent2days()`）を足す。既存の式と同じ定数（`DAYS_GAGE_K`・
   `DAYS_GAGE_MAX`）を使い、対応する関数を doc コメントで示す
2. ゲージの帯のタップ・クリックを受け、位置の割合（帯の左端 0%・
   右端 100% を -50〜+50 に直したもの）から日数を逆算する。今週の月曜から
   その日数ずらした日を含む**週の月曜**へ移動する
3. 移動は既存の `scrollToDate()` を使う（DOM にある週ならスクロール、
   外なら読み直し）。第 1 引数のパスは、`main.html` の `onloadHdr()` と
   同じく `location.pathname` でよい
4. タップできると分かるように CSS（`my.css`）を足す。最小限でよい
5. テストを足す（下記）

## 気をつけること

- **既存のスワイプ・ドラッグと競合させない。** `my.js` の下のほう
  （`touchStartHdr` / `mouseDownHdr` 系）が週送りのために `window` へ
  ハンドラを登録している。ゲージの上での操作がそちらに拾われて週が
  送られたり、逆にゲージのタップが握りつぶされたりしないか確かめること。
  必要なら `stopPropagation()` などを使ってよいが、なぜ要るのかを
  コメントに書く
- **検索モードでは週バーごと出ない**ので、要素が無い前提で書く
  （既存の `dispGage()` が `elGageR0` の有無を見ているのと同じ）
- **針の位置合わせのコードには触らない**（TODO-049・060・066 の経緯がある）
- 範囲の頭打ちは設けない。逆算した日付へそのまま飛ぶ
- ハンドラの登録場所は、既存の書き方（`main.html` のインラインか
  `my.js` か）に合わせて、理由が説明できるほうにする
