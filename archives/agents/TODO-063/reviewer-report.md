## 確認した内容

### 1. 直し方の正しさ・境界

`wday`（月曜 1 〜 日曜 7）に対して、新しい式

```javascript
const days = (1 - wday) + (direction > 0 ? 7 : -7);
```

は「まず `1 - wday` でその週の月曜まで戻し、そこから ±7 日ずらす」という
コメントどおりの計算になっている。`wday` 1〜7、`direction` ±1 の全 14
通りを手計算・`node` で突き合わせて確認した。

- **前へ送る側（`direction <= 0`）**: どの曜日から始めても、必ず
  「今の週の月曜より 7 日前」＝前の週の月曜になる。旧コードは
  `wday==1`（月曜始まり）のときだけ `-7` に補正する特別扱いで、
  それ以外の曜日では `1 - wday` のまま（＝今の週の月曜）になっていた。
  これが依頼書・`TODO.md` に書かれているバグそのもの。新しい式では
  月曜かどうかで場合分けする必要が無くなり、特別扱いも消えている。
- **次へ送る側（`direction > 0`）**: `(1 - wday) + 7` は代数的に旧コードの
  `8 - wday` と完全に一致する（式変形しただけ）。分岐や特別扱いも元々
  無かったので、挙動は 1 ビットも変わっていない。依頼にあった
  「次の週へ送る側が変わっていないか」は、恒等式なので確認するまでも
  なく保証されている。
- **年またぎ・月またぎ**: 生成した `days` を `shiftDays()`
  （`d.setDate(d.getDate() + days)`）に渡すだけで、JS の `Date` が
  月末・年末の繰り上げ／繰り下げを自動でやってくれる。`days` の値が
  大きくなる場合（例: 日曜から前へ送ると `-13`）でも同じ経路を通るので
  問題無い。

### 2. 呼び出し元での挙動

呼び出し元は 3 箇所（720 行目の◀、725 行目の▶、870 行目のスワイプ／
ドラッグの `swipeFinish()` 経由）。いずれも `direction` は `+1` か `-1`
しか渡していない。前へ送る側の修正内容が全呼び出し元に一様に効き、
次へ送る側は既述のとおり変化無し。

### 3. スライドアニメーションとの整合

`slideWeekWrap()` の滑らせ先（`target_x`）は `direction` の符号だけで
決まり、`moveToMonday()` の `days` 計算とは独立している。サーバ側
（`main_handler.py`）は `.my-week-prev` / `.my-week-next` を、表示中の
`date` から単純に ±7 日した週で作っている（`load_sched(date ± 7日)`）。
月曜起点かどうかに関わらず ±7 日は必ず隣の週になるので、今回の修正で
クライアントが要求する `date`（前の週の月曜）と、あらかじめ DOM に
置かれている `.my-week-prev` の週は一致する。

むしろ **修正前は逆に不整合が起きていた**（今回の diff の範囲外の話として
参考まで）。ホームボタンで水曜などに飛んだ直後に◀を押すと、見た目は
`.my-week-prev`（前の週）へスライドするのに、`doGet()` が要求する
`date` は旧コードのバグで「今の週の月曜」のままだったので、スライド後に
表示される内容は前の週ではなく今の週に戻っていたはず。今回の修正で
その不整合も解消されている。
