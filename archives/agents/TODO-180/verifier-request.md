# TODO-180 verifier への依頼

## 目的

ゲージのスライダーから指を離したとき、ページの読み直しをはさんでも針が
今週の位置（50%）を経由しないことを確かめる。あわせて、これまでの針の
動き（ページを読み直した直後の演出・週送り・ホームボタン・月間表示）が
変わっていないことを確かめる。

## 対象

- `src/ytsched/webroot/static/js/gauge.js`（実装。develop の HEAD からの差分）
- `tests/test_browser.py`（テスト 2 件を追加）

変更の中身:

- `sessionStorage` のキーの意味を「直前に見ていた週」から
  「次にページを読み込んだとき、針を置き始める位置」へ変えた
  （`ytsched_gauge_monday` → `ytsched_gauge_start`）
- `dispGauge()` は、ページを読み込んでから初めての呼び出しのときだけ
  出発点を使う。見分けはモジュール内の `gaugePlaced` フラグ。
  TODO-179 で入れた「`style.left` が空か」の分岐は消した
- `gaugeBarPointerUpHdr()` が、ページを読み直す前に離した位置の週を
  出発点として書く

## 確認してほしいこと

1. `mise run lint` と `uv run pytest` が通ること（件数も報告する）
2. playwright で実際に動かして、次を見る。`--datadir` には必ず一時
   ディレクトリを渡すこと
   - **週間表示で +5w（先読みの範囲の外）へドラッグして離す。**
     ページの読み直しが起き、離したあとの `#gauge_r` の `style.left` が
     50% を経由しないこと。最後は移り先の週の位置に居ること
   - **月間表示で +3y へドラッグして離す。** 同上
   - **週間表示で +4w（範囲の内側）へドラッグして離す。** 読み直しが
     起きず、離したあと針が動かないこと（TODO-179 で直した挙動）
   - **ページを読み直した直後の演出が生きていること（TODO-049）。**
     `?date=X` で開いたあと `?date=Y`（離れた週）で開き直すと、針が
     X の位置に transition 無しで置かれてから Y へ動くこと
   - **週送り・ホームボタン・月間表示の切り替え**で針がおかしくならない
     こと（TODO-173 の「ホームボタンで中央へ戻る」を含む）
   - console にエラーが出ないこと
3. 気づいた懸念があれば挙げる
