# TODO-096 の分担

Android の Firefox でアイコンが黒く塗りつぶされる件の修正。

| 担当 | 何を任せたか |
|---|---|
| main | 原因の切り分け、`my.css` と `icons.svg` の修正、描画の目視確認 |
| verifier | `mise run fmt` / `typecheck` / `lint` / `test` と、CSS の前後関係・テンプレートの取りこぼしの確認 |
| wording | コミットに入る `.md` の、前例の無い語 |

## この分担にした理由

- **implementer を分けなかった。** 変更は CSS の宣言 5 行を移すだけで、
  ファイルは 2 つ。複数のファイルにまたがって実装とテストがまとまって
  要る、という目安（`~/.claude/CLAUDE.md`）には当たらない。
- **verifier は分けた。** 規模によらず確認は別の担当に分ける決まり。
  今回は特に、**実装した本人には見えにくい取りこぼしが 2 つあった**。
  `.my-icon-9x` の `stroke-width: 1` が `.my-icon` の `2` に
  負けていないか（詳細度が同じで、CSS の中の前後関係で決まる）と、
  `icons.svg#` を参照している `<svg>` 全部に `my-icon` が付いているか
  （付いていないものがあれば、そこだけ今度は本当に黒くなる）。
  どちらも「直したところ」ではなく「直したせいで壊れうるところ」で、
  依頼書に書き出して見てもらった。
- **reviewer は入れなかった。** スタイルの置き場所を変えるだけで、
  分岐も挙動のロジックも変わらない。TODO-017 で決めた起用の基準
  （挙動や分岐が変わる項目）には当たらない。
- **wording を立てた。** `.md` が入るコミットなので（TODO-025・TODO-026）。
  項目を立てたときの分と、決着させるときの分の 2 回。

## wording の結果への判断（1 回目）

前例なしとして 5 語（消去キー、漏斗、塗りつぶされる、輪郭パス、
shadow tree）が挙がったが、書き換えなかった。

- **「消去キー」「漏斗」は前例があった。** `icons.svg` のコメントで
  この 2 つのアイコンをそう呼んでいる。wording の `git grep` が
  `.svg` を対象から外していたための取りこぼし
- 「輪郭」も archives に前例がある
- 「shadow tree」は Shadow DOM の一般的な用語で、無理に和訳しない
  方針に沿う。このリポジトリでは初出だが造語ではない
- 「塗りつぶされる」は普通の日本語で、活用形の違いによる不一致

## wording の結果への判断（2 回目）

前例なしとして 8 語（軒並み、整形式、ベースパス、潰されない、
実体のタグ、漏れなし、壊れうる、本当に黒くなる）が挙がったが、
書き換えなかった。いずれも普通の日本語か、一般に通用する IT 用語
（「整形式」は XML の well-formed、「ベースパス」は base path）で、
造語ではない。

1 回目で挙がった 5 語は、立てるコミット（`100e594`）で `TODO.md` に
入ったため、2 回目の時点では前例のある語になっている。
