## 確かめること

1. `mise run fmt` / `typecheck` / `lint` / `test` が通ること。
   **`mise run upgradeproject` は走らせない。**
   `tests/test_browser.py` のタイミング依存の失敗は既知（implementer の
   報告を参照）。落ちたら、この変更のせいかどうかを切り分けて報告する

2. **`ytsched fix-id` を実際に動かす。** 一時ディレクトリに、次の 4 通りが
   混ざったデータを自分で作って当てる。`--datadir` には必ず一時
   ディレクトリを指定する（`~/ytsched/data` は絶対に触らない）
   - 旧形式の `sde_id`（UUID でない）
   - 版の付いていない UUID
   - 既に `{UUID}-{版}` の形
   - `-001` のようなゼロ埋め（新しい形式と見なさず振り直されるはず）

   見るところ:
   - `{年}/{月}/{日}.jsonl`・`ToDo.jsonl`・`trash.jsonl` の 3 つが対象に
     入っていること。`.bak`・`.cgi` が触られていないこと
   - `sde_id` 以外のキーが、値も並び順も変わっていないこと
     （`trash.jsonl` の `trashed_at` が先頭のままかも見る）
   - 既に UUID だった行は、UUID が保たれて `-1` が付くこと
   - 既に新しい形式の行しか無いファイルは、書かれない（更新時刻が
     動かない）こと
   - `--dry-run` で書き出されないこと
   - 出力の件数が実際と合っていること

3. **アプリを起動して、画面で一通り確かめる。**
   `--datadir` は一時ディレクトリ。`docs/Developer.md` に起動の仕方がある
   - 予定を作る → ID が `{UUID}-1` になること
   - その予定を編集して保存する → 新しい予定の版が `2` になり、
     ゴミ箱に版 `1` の行が入ること
   - もう一度編集する → 版が `3` になり、ゴミ箱が版 `1`・`2` の
     2 行になること
   - ゴミ箱画面で、その 3 つが**同じグループにまとまって**表示され、
     各行に版が出ること
   - `?sde_id=` に**版まで含めた ID**を渡しても、**UUID 部分だけ**を
     渡しても、同じグループが出ること
   - ゴミ箱から復活させる → UUID が引き継がれ、版が既存のどれとも
     ぶつからないこと（生きている予定の版とも、ゴミ箱の版とも）
   - 予定を削除する → ゴミ箱の行の ID が、削除した予定の ID のままで
     あること（版が増えないこと）
   - ゴミ箱からの完全削除（1 件・複数件）が、狙った行だけを消すこと

4. **旧形式の `sde_id` のまま編集したとき**の挙動。`fix-id` を当てる前の
   データを想定して、旧形式の予定を編集すると、新しい ID
   （`{UUID}-1`）が発行され、落ちないことを確かめる
