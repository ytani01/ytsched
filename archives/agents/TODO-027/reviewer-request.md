## 特に見てほしいところ

この項目は**分岐と条件式が動いている**。テストが通ることでは捕まらない
ずれを探してほしい。

1. `get_conf_arg()` の落ち方が変わっている。実装者は「引数が不正なら
   `Conf.cgi` の値 → 既定値の順に落ちる」ようにしたと書いている
   （依頼書の文面とはここだけ違う）。**この形で、
   `empty_is_given` との組み合わせも含めて破綻していないか。**
   4 か所（`search_str`/`filter_str`/`search_n`/`todo_days`）それぞれで
   今までと結果が変わる入力が無いか
2. `get_date()` の優先順位（`year`+`month`+`day` → `modified_date` →
   `date` → `cur_day` → 今日）が変わっていないか。**不正な値を
   「無かった」ことにすると、優先順位の下の値が繰り上がる**。それが
   意図どおりか
3. `ymd2date()` は `year`/`month`/`day` の 3 つが揃ったときだけ効くのか。
   1 つだけ不正なときの扱いは今までと同じか
4. 変換に失敗したときに `set_conf()` が呼ばれない経路になっているか。
   **抜け道が残っていないか**
5. 警告ログの出し方が `CLAUDE.md` の決まり（`mylog` のラッパ、
   `__log = getLogger(__qualname__)`）に沿っているか。出しすぎ／
   足りなさすぎが無いか
6. 型の付け方（PEP 695 のジェネリック）が読みやすいか。この
   リポジトリの他の書き方から浮いていないか
7. 足したテストが、**挙動を固定するものになっているか**（実装に
   合わせただけになっていないか）。書き直したゴールデンマスターテストが、
   変更後の挙動をきちんと押さえているか
