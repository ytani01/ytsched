## 2. 針と基準線の重なり方 — 見た目は○、ただし調べ方に注意が要った

最初に `getBoundingClientRect()` の**コンテナ div/svg の箱**で比較したところ、
以下のように見えた。

| | `#gage_r`（針の箱）中心 | `#gage_r_base`（基準線の箱）中心 | 差 |
|---|---|---|---|
| old | 1870.5px | 1889.0px | **18.5px** |
| new | 1888.5px | 1888.5px | **0px** |

これだけを見ると「新版は重なり方が変わった」ように見える。しかし、これは
TODO-042 で見た現象と同じ罠だった。**old（FA）の箱は `font-size` から来る
高さ（36px）を持ち、実際に見える三角形の字面（約 21px）よりずっと大きい。
new（SVG）は `viewBox` にぴったり合わせた箱（21px）なので、箱の中心と
字面の中心がほぼ一致する。** つまり「箱の中心」を比べると old だけが
字面からずれて見える指標になってしまい、比較として成立しない。

そこで、スクリーンショットの**画素そのもの**（実際に目に見える三角形と
`＝` の位置）を直接調べ直した。

| | 三角の bbox（y） | `＝` の bbox（y） |
|---|---|---|
| old | 2021〜2041 | 2030〜2033 |
| new | 2022〜2041 | 2030〜2033 |

**`＝` の位置は 1 ピクセルも変わらず、三角の範囲もほぼ同じ（1px の差は
アンチエイリアスの閾値程度）。実際に見える重なり方は変わっていない。**
`compare -metric AE` で 2 枚を比較しても、差分のある画素はすべて
`x: 0〜14, y: 2020〜2043` の範囲（＝ゲージの領域そのもの）に収まっており、
それ以外は 1 画素も違わない（下記「4」参照）。

拡大画像（`todo043_before_gage_zoom.png` / `todo043_after_gage_zoom.png`）
を見比べても、`＝` が三角の上部〜中央に乗る構図は同じに見える。

## 3. 縦位置・目盛りラベル — ○

`getBoundingClientRect()` 実測（`old` / `new`）。

| 要素 | `top`（old） | `top`（new） |
|---|---|---|
| `#gage_r0`（-30y ラベル） | 1597px | 1597px |
| `#gage_r1`（-10y ラベル） | 1631px | 1631px |
| `#gage_r2`（-3y ラベル） | 1667px | 1667px |

`left` / `width` も含めて完全一致。`dispGage()` が決める縦位置（`bottom`
のスタイル文字列）も、`#gage_r` は old/new とも `"1968.5px"` で一致
（`elGageRBase.style.bottom` は old が `centerY - 9`、new が `centerY` に
変わったが、`dispGage('2026-08-24')` で针を基準線に揃えた状態では両者とも
同じ `"1968.5px"` になり、見た目の重なりも上記 2 のとおり変わらない）。

## 見つかった不具合・気になった点

- **実装に問題は見つからなかった。** 針の左端・重なり方・縦位置・
  目盛りラベルとも、実際の画素で見るかぎり old（HEAD）と new（作業ツリー）
  で変わっていない
- **確認の途中で見つけた、次に同種の作業をする人への注意点。**
  `getBoundingClientRect()` は「見た目」の指標として万能ではない。
  今回のように、コンテナの箱の大きさが図形の実寸と違う場合
  （フォントアイコンのように `font-size` 由来の余白がある場合など）、
  「箱の中心」で比べると実際には動いていないものが動いたように見える
  ことがある。**最終的な判断は画素を直接読むべき**（TODO-042 の
  「実測」も画素までは踏み込んでいなかった）
- スクリーンショットの `--window-size` と `document.documentElement
  .clientHeight` が一致しない（`4000` 指定に対し実測 `3857`。差は約
  143px）ことに途中で気づいた。今回は old/new とも同じ量ずれていたので
  比較には影響しなかったが、**単独の版で `getBoundingClientRect()` の
  値からスクリーンショットの画素位置を逆算するときは、この差分を
  意識しないとズレる**
