## 誰に何を担当させたか

| 担当 | 役割 | 報告 |
|------|------|------|
| `general-purpose`（grep 側） | CodeGraph を使わず、Grep/Read だけで復元経路を調べる | [grep-report.md](grep-report.md) |
| `general-purpose`（CodeGraph 側） | Read/Grep を使わず、CodeGraph だけで同じ問いを調べる | [codegraph-report.md](codegraph-report.md) |
| `verifier` | `CLAUDE.md` に書いたコマンド例と数値の主張を、実際に叩いて確かめる | [verifier-report.md](verifier-report.md) |

## その分担にした理由

**2 本の `general-purpose` は、作業の担当ではなく測定対象。** この項目の
目的は「CodeGraph がトークンを減らすか」を測ることなので、同じ問いを
道具だけ変えて解かせ、消費を比べる必要があった。

- **`Explore` ではなく `general-purpose` にした。** `Explore` は
  `CLAUDE.md` を読み込まないので、条件が揃わない
- **2 本ともモデルを `sonnet` に上書きした。** 定義の既定に任せると、
  片方だけモデルが変わったときに消費の差が道具の差か
  モデルの差か分からなくなる
- **道具の制限は依頼文で明示し、「理由を問わず守れ」と書いた。**
  片方が禁止された道具に手を伸ばすと測定が壊れるため
- **CodeGraph 側には「まず日本語で問い、空振りしたら英語に切り替えろ」と
  指示した。** 切り替えのコストも実務では発生するので、それを込みで
  測るため。結果として日本語の空振りが 3 回記録され、原因究明の
  きっかけになった

**`verifier` は見込みに入れていなかった。** 文書だけの項目なので不要と
考えたが、`CLAUDE.md` にコマンド例を 3 つ書いた時点で「書いたとおりに
試せるもの」に該当した（TODO-017 で決めた基準）。着手後に足した。

**測定の前半（バイト数の比較、日本語が無視されることの切り分け）は
main が抱えた。** これが料金の 76% を占めた原因で、手順が決まっていて
判断が要らない作業なので `runner` に投げるべきだった。詳しくは項目の
ファイルの「分担の振り返り」にある。
