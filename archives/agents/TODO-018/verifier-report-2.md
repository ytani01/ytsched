## 4. 移行のあとで画面の見え方が変わらないか — いちばん大事な数字は
一致。分類の切り分けに 1 点補足が要る

`src/ytsched/ytsched.py` の `htmlstr2text()` を import し、
「旧の画面」= `html.unescape(htmlstr2text(生の値))`、「新の値」=
（`<br />`→改行、`html.unescape()` を 2 回、NBSP→半角空白の順、全角
括弧はそのまま）で、年別ファイル（`ToDo.cgi` を除く、成功デコード分
＋ 13 件の "fail" ファイルを `errors="replace"` で読んだもの）の
`type` `title` `place` `detail` 4 フィールド × 13407 行を突き合わせた。

- **総項目数 53628、一致しなかった項目数 168**（両方とも文書の数字と
  完全に一致。`13407 × 4 = 53628`）
- `base.html` が `{% autoescape None %}` であること（29 行目）、
  `sde.html` が `sde.title` `sde.place` `detail`（= `sde.detail`）を
  そのまま出力していること（エスケープフィルタなし）を確認した。
  「旧の画面 = ブラウザが実体参照を 1 回デコードしたもの」という前提は
  妥当
- `SchedDataFile.load()` は `type` `title` `place` `detail` の
  4 フィールドすべてに `htmlstr2text()` を掛けている（`title` `place`
  `type` は 1 回、`detail` は `load()` と `SchedDataEnt.__init__` の
  両方で 2 回）。**`detail` の 2 回適用と 1 回適用の結果が食い違う
  行は実データ中に 0 件**だった（`htmlstr2text()` はこのデータに対して
  冪等）ので、この二重適用は今回の数字に影響していない

**168 件の内訳を、文書の分類基準（全角括弧だけで説明できるか／NBSP
だけで説明できるか）で機械的に仕分け直すと:**

| 分類 | 件数 |
| --- | --- |
| 全角括弧の差だけで説明できる | 152 |
| NBSP の差だけで説明できる | 4 |
| 数値文字参照の差だけで説明できる（全角括弧の差は無い） | 7 |
| **全角括弧の差と数値文字参照の差が同じ項目に同居** | **5** |

つまり文書は、括弧と数値文字参照の両方が絡む 5 項目を「全角括弧」
側に数えている。合計 168 件、想定外の原因（3 分類のどれにも
当てはまらないもの）は **0 件**で、「想定していなかった違いは
無かった」という結論は正しい。ただし**表の 3 行は排他的な分類では

残した（手順 6）」＝ 157 件と読むと、そのうち 5 件は数値文字参照の
戻し（手順 5）も同時に効いている、という点は文書から読み取れない。
判断が要る点として報告する（数字自体の誤りではない）

なお `ToDo.cgi`（9 行・36 項目）は、この 53628 件の集計に**含まれて
