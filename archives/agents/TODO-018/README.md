# TODO-018 の分担

## 誰に何を担当させたか

| 担当 | 何をしたか | 報告 |
| --- | --- | --- |
| main | 現状の調査、選択肢の整理、仕様の決定、`docs/data-format.md` の執筆 | — |
| verifier | 仕様書に書いたことが成立するかの確認 | [verifier-report.md](verifier-report.md)（依頼は [verifier-request.md](verifier-request.md)） |

## なぜこの分担にしたか

項目を立てたときの見込みは `担当 = main のみ` だった。「決めるだけの
項目」で、確かめるものが無いと考えたため。

着手して仕様が固まった時点で、**確かめられる中身があると分かったので
verifier を足した**。`docs/data-format.md` は文書だが、書式が揃っているか
だけの文書ではなく、次のものが実際に試せる。

- 載せた JSON Lines のサンプル行が `json` で読めるか
- 「壊れた行はその行だけ飛ばす」が本当に書けるか
- 全角括弧を半角にして小文字化するだけで、「重要」「取り消し」の判定が
  全角・半角のどちらでも効くか
- 旧形式からの移行手順のとおりに変換できるか、手順に抜けが無いか

加えて、この文書は**旧形式の問題点を実測にもとづいて挙げている**。
その引用が現状のコードの挙動と合っているかは、書いた本人が確かめると
「そう書いたのだからそうだろう」で通してしまう。TODO-017 で決めた
「書式の確認だけなら main、試せる手順があるなら分ける」に当てはまる。

reviewer は入れていない。コードを変えていないので、分岐や条件式の意味が
変わったかを見る対象が無い。

implementer も使っていない。この項目で作ったのは文書だけで、実装と移行
ツールは別の項目にしたため。
