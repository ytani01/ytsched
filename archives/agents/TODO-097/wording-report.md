## 前例の無い語（件数の少ない順）

### 1. `provides` / `depends on`（英語のまま）

- **箇所**: `implementer-report.md` の「変更ファイル」節でほぼ全行
  （`provides: ytState。depends: なし` など）。`README.md`（TODO-097）でも
  「provides / depends on の向き・帰属」。`verifier-report.md` も
  「provides / depends on の向き」。
- **件数**: `provides` 前例なし / `depends on` 前例なし
  （`provides:` も前例なし）。
- **見立て**: モジュール依存の一般的な用語ではあるが、この項目の TODO.md
  本文と成果物のコメントでは日本語の「外へ出すもの」「外から使うもの」で
  統一されている。報告だけ英語に振れており、言い換え候補は
  「外へ出すもの / 外から使うもの」。判断は main。

### 2. 過大近似 / 過大な近似

- **箇所**: `TODO-097.md`「verifier が挙げた細かい過大近似 4 点を main が
  直した」。`README.md`（TODO-097）に同文。`verifier-report.md`
  「過大な近似。」（nav.js の項）。
- **件数**: 前例なし（`git grep -cF 過大 HEAD` が当たるのは
  `TODO-029/wording-report.md` で、これは過去の wording が候補として
  挙げた行。本文での使用例ではない）。
- **見立て**: over-approximation の直訳的な言い回しで、造語くさい。
  「ひとまとめにしすぎ」「まとめすぎて実態より広く見える」あたりが
  言い換え候補。

### 3. 代表表

- **箇所**: `TODO-097.md`「### TODO.md の代表表になかった依存（想定と
  違ったもの）」。`implementer-report.md`「TODO.md の代表表になかった依存」。
- **件数**: 前例なし（`git grep -cF 代表例 HEAD` は
  `TODO-052` に 1 件あるが「代表表」という複合語は無い）。
- **見立て**: 「代表例だけを載せた表」を 1 語に縮めた造語。直後の本文では
  「TODO.md の表は代表例だけだった」と普通に書けている。言い換え候補は
  「TODO.md の表」。

### 4. 由来ファイル

- **箇所**: `TODO-097.md`「見出しを直し各行に由来ファイルを付けた」
  「各行に由来ファイルを付けた」。`README.md`（TODO-097）に同文。
- **件数**: 前例なし。
- **見立て**: 意味は取れるが独自の複合語。名前がどのファイルで定義されて
  いるかを指す。言い換え候補は「定義元（のファイル）」。

### 5. 属性ハンドラ

- **箇所**: `TODO-097.md`「属性ハンドラ（`onmousedown=` など）だけを採り」。
  `implementer-report.md`「実際の関数呼び出し・属性ハンドラ」。
- **件数**: 前例なし。
- **見立て**: HTML の要素属性に書いたイベントハンドラ（`onmousedown=`）の
  こと。短縮として通じるが独自。言い換え候補は「HTML 属性のイベント
  ハンドラ」「インラインの `on*` 属性」。判断できない部分は main へ。

### 6. 前方参照

- **箇所**: `TODO-097.md`「実行時にしか呼ばれず前方参照でよい」。
  `implementer-report.md`「前方参照でよい」。`README.md`（TODO-097）に同文。
- **件数**: 前例なし。
- **見立て**: プログラミングの一般用語（forward reference）。造語ではない。
  この文脈（読み込み順より後で定義される関数を実行時に呼ぶ）で自然。

### 7. 裏取り

- **箇所**: `README.md`（TODO-097）「そこを grep で裏取りさせる」。
  `verifier-report.md`「grep で全項目を裏取りした」。
- **件数**: 前例なし。
- **見立て**: 報道・調査で定着した一般語。造語ではないが、これまでの
  wording・verifier 報告では「確認」「検証」が使われてきた。言い換え候補は

### 8. 暗黙の仕様
