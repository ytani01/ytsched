# TODO-069 の分担

| 担当 | 何を見たか | 報告 |
|------|-----------|------|
| main | 設計と実装（サーバ・テンプレート・CSS・JavaScript・テスト・文書） | — |
| reviewer | 状態の取りこぼし、`id` を全週に付けた影響、後始末 | [reviewer-report.md](reviewer-report.md) |
| verifier | テスト・lint の実行と、ブラウザでの動作確認・速さの測定 | [verifier-report.md](verifier-report.md) |
| wording | コミットに入る `.md` の、前例の無い語 | [wording-report.md](wording-report.md) |

`wording-report.md` は 2 回ある。1 回目は項目を立て直したとき
（`docs(todo): TODO-069 を精査して…`）の `TODO.md` が対象。

## この分担にした理由

- **実装は main で行った。** 込み入っているのは JavaScript の状態の
  持ち方（どの週を通常フローに残すか、週を移ったときに何を揃えるか）
  で、そこを分けて渡すと前提を書き写す手間のほうが大きい
- **reviewer を入れた。** 週移動の経路（スワイプ・◀▶・←→・戻る/進む・
  ホームボタン）がまとめて変わり、**分岐そのものが変わる**項目。
  `~/.claude/CLAUDE.md` の「挙動や分岐が変わる項目には入れる」に当たる。
  とくに「ページを読み直していたときはサーバが全部描き直していたものを、
  JavaScript が揃え直す」形なので、**揃え忘れは実装者からは見えにくい**
- **確認も分けた。** 見た目と操作の変更はテストが通ることでは
  確かめられない（TODO-042・TODO-066・TODO-067 と同じ）

## 効いたところ

- **reviewer が、検索モードの「戻る」が毎回読み直しになる退行を
  見つけた。** 週送りの経路ばかり見ていて、`popstateHdr()` で
  「週が分からない」を「範囲の外」と取り違えていた。テストは 453 件
  すべて通っていたので、**テストが通ることでは出てこない種類の指摘**
- **verifier の速度の数字は、そのまま受け取らずに測り直した。**
  変更前と変更後で終わりの見方が違っていて、変更後のほうが遅いという
  結果になっていた。同じ測り方に揃えると逆（772ms → 390ms）。
  verifier 自身が「断定できるか自信が無い」と付けて報告していたので、
  そこで止まらずに済んだ
- **verifier は `git stash` を使って変更前と比べた。** 依頼で
  `git stash pop` を指示していたので戻ったが、**その間 main は
  作業ツリーを触れない**（実際、退避されている最中に編集して
  やり直しになった）。次からは `git archive HEAD` を別ディレクトリへ
  展開させるほうがよい
