# TODO-146 reviewer への依頼

## 目的

TODO-146（CSS のクラス名を役割の名前へ変える）の変更を読み、
**元の重ね掛けと同じ計算値になっているか**、設計として妥当かを見る。
**コードは直さない。** 見つけたことは報告する。

## 前提

- `TODO.md` の「## TODO-146.」の節
- 実装者の報告 `archives/agents/TODO-146/implementer-report.md`
- 変更前の状態は `git show HEAD:src/ytsched/webroot/static/css/my.css`
  と `git show HEAD:src/ytsched/webroot/templates/<name>.html` で読める

## 見てほしいこと

1. **畳み込みの写し漏れ・写し間違い。** テンプレートの各要素について、
   変更前の `class="..."` に並んでいたユーティリティを展開し
   （ショートハンドも展開する）、変更後の役割クラス 1 つが同じ
   プロパティ値を持っているかを 1 要素ずつ突き合わせる。ここが本題
2. **`.row > *` の扱い。** 変更前は `.row > *` が
   `min-width: 0` とガター由来のパディングをすべての列に掛けていた。
   各列の役割クラスにきちんと配られているか。落ちている列は無いか
3. **`.my-row-middle > *` / `> .text-end` の flex 化。** 子セレクタで
   効いていたものが、親のクラスが変わった後も同じ要素に効いているか
4. **`!important` を全廃したことの妥当性。** 特に `.d-none` を畳み込んだ
   結果、メニューの開閉（`#menu-sw:checked ~ .my-bar-content`）と
   詳細の開閉（`.my-longtext-sw:checked ~ ...`）で、詳細度と
   ソース順のどちらが効いているか。並べ替えると黙って壊れる箇所があれば
   コメントで書き残されているか
5. **`.my-longtext` の `min-width: 0` が、親の直接の子であることに
   依存している件**（TODO-045・TODO-047）。入れ子や親クラスが変わって
   いないか。変わっているなら `text-overflow: ellipsis` が効くか
6. **命名の一貫性。** 既存の `my-*` の付け方（`my-sde-*` `my-date-*`
   `my-menu-*` など）と揃っているか。役割を表していない名前、
   ユーティリティ名を `my-` で置いただけの名前が無いか
   （残した修飾クラス `my-align-middle` `my-fw-bold` `my-row-end` は
   実装者が理由を書いているので、その理由が妥当かを見る）
7. **使われていない定義・定義の無いクラス**が無いか
8. ライセンス表記（`my.css` 先頭・`docs/Developer.md`）が、実態と
   合っているか。写した値の列挙に漏れが無いか
