# TODO-073 の分担

| 担当 | モデル | 何を任せたか |
|------|--------|--------------|
| main | Opus 5 | 置換の範囲決め、実装 |
| [wording](wording-report.md) | 定義ファイルによる | TODO-073 節の前例の無い語を挙げる |
| [verifier](verifier-report.md) | 定義ファイルによる | 差分の点検、lint・テスト、実アプリの起動確認 |

## なぜこの分担にしたか

変えたのは著作権表示の文字列だけで、設計の判断は無い。範囲（フッターだけか
ソース全体か、年を範囲にするか固定にするか）は着手前に利用者に聞いて
決まっていたので、実装は main が持った。

**確認は分けた。** コードやファイルを変える項目では、規模によらず確認を
別の担当にする決まり（`~/.claude/CLAUDE.md`）。今回はそれに加えて、
一括置換に特有の危うさがあった。

- 正規表現での一括置換は、意図しない箇所まで書き換える。実際、main が
  最初に走らせたときに `TODO.md` の説明文（「`(c) 2020 Yoichi
  Tanibayashi` のままになっている」）まで置換してしまった。**自分で
  書いた正規表現の穴は自分では見えにくい**ので、差分の点検を分けた
- `docs/licenses/` には他者（Bootstrap）の著作権表示があり、これを
  巻き込んでいないかは必ず見る必要がある

`.md` が入るコミットなので `wording` も立てた。

- [wording の報告](wording-report.md)
- [verifier の報告](verifier-report.md)
