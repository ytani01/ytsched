# TODO-169 の分担

| 担当 | 依頼した内容 | 報告 |
| --- | --- | --- |
| main | コードとデータ形式を読み、`docs/image-attach-proposal.md` を書く | — |
| verifier | 提案書に書いたコード・データ形式についての記述 12 点の事実確認 | [verifier-report.md](verifier-report.md) |

## この分担にした理由

立てたときの見込みは `main のみ` だった。方針を決めるだけの項目で、
確かめるものが無いと見たため。

着手して書いてみると、提案書の中身は**現行コードから読み取った事実**が
土台になっていた（更新が内部で削除→追加であること、復活で `sde_id` が
変わること、`static/js/` に `fetch()` が 1 つも無いこと、依存が 3 つ
だけであること、など）。ここが違っていると提案そのものが崩れるので、
事実の部分だけを verifier に確かめさせた。設計案の良し悪しは
判断させていない（それは利用者と main が決める）。

テスト・lint は走らせていない。コードを 1 行も変えていないため。

## 結果

12 項目すべて「合っている」。事実誤認は無し。
