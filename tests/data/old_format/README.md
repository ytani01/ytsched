# 移行元（旧形式）のテストデータ

JSON Lines への移行ツール（TODO-020）のためのテストデータ。
**中身は架空**で、実データの構造だけを写してある（実データは個人の
予定そのものなのでリポジトリに入れられない）。

**手で編集しない。** `tests/make_test_data.py` が生成する。

```sh
uv run python tests/make_test_data.py
```

このディレクトリを、旧形式のデータディレクトリ（`~/ytsched/data`）の
代わりとして使う。形式そのものの決まりは `docs/data-format.md` にある。

## 押さえておくところ

- **`sde_id` は UUID ではない。** 実データと同じく `{epoch}-{連番}` の形で、
  長さは 13・15・16・17・18 文字が混じる
- **同じ `sde_id` が 3 回出てくる。** `1627783341-8621308` が
  `2021/08/01.cgi` に 1 行、`2021/08/02.cgi` に 2 行。**同じファイルの
  中でも重複する**
- **どちらでも読めないバイトは `\xad` の 1 バイト。** 実データで
  「どちらでも読めない」13 ファイルを調べたら、壊れていたのはこの形
  だった（euc_jp の 2 バイト文字の片割れが落ちたもの）。行ごとに
  デコードすれば、その行も `errors="replace"` で残せる
- **U+2028（LINE SEPARATOR）に注意。** `2021/08/02.cgi` の 3 行目の
  `detail` に入っている。`str.splitlines()` で行を切ると 1 件が 2 行に
  割れる（`split("\n")` なら割れない）。実データにも 1 件あった
- **列の数が 7 でない行は、実データには無かった。** 移行の手順が
  「7 個に満たなければ空文字で埋める」「8 個目から先は `detail` の
  続きとしてつなぎ直す」と決めているので、それを試せるように入れてある
- `2021/08/01.cgi.bak` は `.gitignore` の `*.bak` に当たるので、
  打ち消しの指定を入れてある
