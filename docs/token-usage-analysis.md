# トークン消費の分析

**この文書は分析の結果と、そこから決めた進め方をまとめたもの**（TODO-175）。
数え方そのものは `CLAUDE.md` の「トークン消費量の記録」と
`tools/token-usage.py` にある。

## 結論（先に）

1. **料金の 3 分の 2 は `cache_read`**、つまり同じ会話を何度も読み直す
   ぶんに払っている。**会話を短く保つことが、いちばん効く。**
2. **main が 73%。** サブエージェントを増やしても料金はほとんど増えない。
   **確認の担当を削る節約には、伸びしろが無い。**
3. **高くつくのは、main が長い会話で実装まで抱え込んだ項目。**
   変更量あたりで 1.6 倍かかっている。

## 何を数えたか

| | |
|---|---|
| 期間 | 2026-08-23 〜 2026-09-03 21:03 ごろ（この分析を始めた時点） |
| リクエスト | 20,161 |
| 概算 | **$852** |

**この合計は測った時点のもの。** 元になっている transcript には、この
分析をしている会話自身も記録され続けるので、同じ集計を後で走らせると
増える（この項目の中で確認のやり取りをしただけで、リクエストは
20,177 に増えていた）。自分自身を測るときに付いて回る性質で、以下の
担当別・会話別の内訳も同じ時点のもの。

TODO 項目ごとの記録は、`archives/todo/` の 173 件のうち **99 件**にある
（概算料金を入れ始めたのは TODO-044 から）。合計 $508、平均 $5.13、
中央値 $3.30。

**条件はそろっていない。** main のモデルも effort も担当も項目ごとに
違い、`--since` を付け忘れて隣の項目を巻き込んだ記録もある。
以下は傾向として読むもので、1 件ずつの比較には使えない。

## 何に払っているか

### 内訳は cache_read が 3 分の 2

| | 料金 | 割合 |
|---|---|---|
| `cache_read` | $562.6 | **66.0%** |
| `cache_creation` | $169.8 | 19.9% |
| `output` | $119.8 | 14.1% |

コンテキストはリクエストのたびに丸ごと払い直す。**一度会話に載せたものは、
その会話が終わるまで毎回料金がかかる。** 書いた量（`output`）は 14% しか
なく、**何を書いたかより、どれだけ長い会話で書いたかで料金が決まる。**

### 担当別では main が 73%

| 担当 | リクエスト | 1 回あたりのコンテキスト長 | 料金 | 割合 |
|------|------|------|------|------|
| main | 8,842 | 105,927 | $619.7 | **72.7%** |
| implementer | 4,370 | 85,548 | $126.9 | 14.9% |
| verifier | 4,460 | 44,004 | $58.5 | 6.9% |
| reviewer | 1,233 | 49,800 | $28.9 | 3.4% |
| wording | 1,103 | 31,300 | $16.4 | 1.9% |
| writer | 113 | 43,041 | $1.7 | 0.2% |
| runner | 40 | 15,743 | $0.2 | 0.0% |

verifier は main とほぼ同じ回数のリクエストを出しているのに、料金は
10 分の 1 以下。**新しい会話で始まるのでコンテキスト長が短いから**で、
同じ作業でも main が会話の末尾でやるのとは桁が違う。**担当を分けること
自体が、コンテキスト長を短く保つ側に効いている。**

### 会話は進むほど高くなる

main の会話 170 本について、「何回目のリクエストか」ごとにコンテキスト長の
中央値を出した。

| 何回目 | 数えた会話 | コンテキスト長の中央値 | その 1 回の料金 |
|------|------|------|------|
| 1 | 170 | 38,141 | $0.019 |
| 10 | 156 | 59,936 | $0.030 |
| 30 | 109 | 89,591 | $0.045 |
| 50 | 70 | 113,322 | $0.057 |
| 80 | 22 | 147,838 | $0.074 |
| 120 | 11 | 188,081 | $0.094 |
| 200 | 3 | 244,826 | $0.122 |

会話の頭では 1 回 $0.02 だが、120 回目には $0.09 で **5 倍**。会話の長さの
中央値は 43 回、最長は 705 回だった。

長さごとにまとめると、**長い会話が料金を持っていっている**。

| 会話の長さ | 本数 | リクエスト | 料金 | 割合 | 1 回あたり |
|------|------|------|------|------|------|
| 1〜19 回 | 42 | 483 | $30.0 | 4.8% | $0.062 |
| 20〜49 回 | 58 | 2,054 | $125.7 | 20.2% | $0.061 |
| 50〜99 回 | 53 | 3,348 | $216.8 | 34.8% | $0.065 |
| **100 回以上** | **17** | 3,007 | **$250.7** | **40.2%** | $0.083 |

**100 回を超えた 17 本（全体の 10%）が、main の料金の 40% を占める。**

## 高くつく項目の特徴

高額な上位 5 件のうち 3 件は main の割合が 87% 以上、残り 2 件
（TODO-047・TODO-049）は implementer が多めに動いている。**割合が低くても
高額になる**のは、implementer に出しても、その報告を受けた main の会話
自体が長ければ料金がかさむため。

| 項目 | 料金 | main の割合 |
|---|---|---|
| TODO-077. `fix` で `.bak` が中間状態に上書きされるのを直す | $43.8 | 96% |
| TODO-069. 数ヶ月ぶんの週を DOM に持ち、週移動でページを読み直さない | $21.6 | 91% |
| TODO-047. Bootstrap をやめて、素の CSS にする | $19.7 | 60% |
| TODO-049. 1 画面 1 週間の表示にする | $17.8 | 46% |
| TODO-048. Font Awesome をやめて、自作の SVG アイコンにする | $16.4 | 87% |

TODO-077 は 1 件で $43.8、記録のある 99 件の合計の 8.6% にあたる。
**料金の 89% が cache_read。** main が 533 メッセージを長い会話の中で
出していた（この 1 件から `~/.claude/CLAUDE.md` の「担当の完了を
ポーリングしない」が決まった）。

変更量でならすと、差はもっとはっきりする（変更 30 行以上の 81 件。
行数は `git show --numstat` を `archives/` と `TODO.md` を除いて
コミットごとに合算したもの）。

| | 件数 | 100 行あたりの料金（中央値） |
|---|---|---|
| implementer に出した | 45 | $1.83 |
| main が実装した | 36 | $3.01 |
| **main の割合 85% 以上** | 22 | **$3.59** |

**main が自分で実装した項目は、変更量あたりで 1.6 倍かかる。**
implementer に出せば、その作業は 8.5 万トークンの新しい会話で走るが、
main が抱えると 10.6 万トークンの会話がさらに伸びていく。

見た目の調整（CSS の微修正、スクリーンショットを見ながらの往復）が
これに当たりやすい。TODO-063 は 13 行の修正で $7.9、TODO-059 は 38 行で
$8.3 かかっている。**変更はごくわずかでも、確かめる往復が多いと高くつく。**

## 効かない節約

### 確認の担当を削っても、ほとんど減らない

1 件あたりの平均は verifier $0.44、reviewer $0.60、wording $0.18。
3 つ全部を毎回立てても $1.2 で、項目 1 件の中央値 $3.30 の 4 割にもならない。
**品質を落とす代わりに得られるものが小さすぎる。**

### 定型作業の自動化も効かない

TODO-052 で測って結論が出ている。項目を立てる・アーカイブする作業を
スクリプトにまとめるとリクエストは 15 回から 5 回に減るが、
**`/clear` してからやるほうが 3 倍効く**（$2.6 → $1.0 に対し、$2.6 → $0.3）。
理由は同じで、**回数よりコンテキスト長のほうが効く**から。

## どうすべきか

### 1. 会話を切る（いちばん効く）

- **1 つの会話で 1 つの項目まで。** 項目のコミットが済んだら `/clear`
- **アーカイブの前に必ず `/clear`。** 実施をやり切った直後がいちばん
  コンテキストが長く、いちばん安く済ませられる場所でもある。
  書く材料（きっかけ・やったこと・テスト）は
  `archives/agents/TODO-NNN/*-report.md` にあるので、切っても書ける
- **50 回を超えたら、切れないか考える。** 50 回目のリクエストは
  1 回目の 3 倍かかっている。まだ続きがあるなら、決まったことを
  ファイルに書き出してから切る

### 2. main に実装を抱えさせない

- **試行錯誤が要る実装は implementer に出す。** 何度も直しては確かめる
  作業ほど、短い会話でやる価値が大きい
- **調べものも、範囲が広いなら担当に出す。** main がファイルを次々
  読むと、読んだ全部がその会話の最後まで料金として乗り続ける

### 3. 見た目の調整は、往復の回数を意識する

- スクリーンショットを見て直す作業は、**確かめたい点をまとめて 1 往復に**
  する。1 点ずつ見ると、そのたびに会話が伸びる
- 画像は会話に載ると重い。**同じ画像を何度も貼り直さない**

### 4. 確認の担当は省かない

安いので、削る判断をする意味が無い。`~/.claude/CLAUDE.md` の
「コードやファイルを変える項目では、確認の担当を別のサブエージェントに
分ける」は、料金の面からも支持される。

### 5. 見込みから外れたら、組み直す

見込みの行と実施の行に出てくる担当の顔ぶれ（implementer・verifier・
reviewer・wording・writer・runner。回数や「main のみ」は無視し、
居るかどうかだけを見る）が一致した 68 件は中央値 $2.65、増えたり
減ったりした 31 件は $5.20 だった。規模を読み違えた項目が高くなるのは
当然だが、**外れたと気づいた時点で会話を切って組み直す**ほうが、
そのまま main で続けるより安い。

## 効いているか

| TODO-040〜059 | 15 | $6.80 | $3.69 |
| TODO-060〜079 | 17 | $3.30 | $3.09 |
| TODO-080〜099 | 19 | $3.20 | $1.67 |
| TODO-100〜119 | 11 | $3.30 | $2.32 |
| TODO-120〜139 | 15 | $2.30 | $2.40 |
| TODO-140〜159 | 9 | $2.40 | $2.86 |
| TODO-160〜179 | 13 | $3.10 | $2.50 |

**TODO-040〜059（TODO-052 で `/clear` を決めた帯）に比べると下がったが、
TODO-080〜099 より先は横ばいで、はっきり下がり続けているとは言えない。**

$2.3〜3.3 の間で行き来している。TODO-160〜179 でやや上がっているのは、
この帯が見た目の調整（上の「3. 見た目の調整は…」）に寄っているため。
**さらに下げる余地があるかは、この表の続きを見て判断する。**
